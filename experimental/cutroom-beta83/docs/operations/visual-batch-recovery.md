# 视觉批次中断后的有证据恢复

本说明面向维护者。恢复只决定哪些源窗口可以重新排队，不修改原批次的 `unknown` 历史、付费状态或观察内容，不自动调用模型。

## 默认边界

- 活跃或未取消的作业阻塞整个原范围。
- 已取消且只有一次串行执行的旧协议批次：连续终态回执后的首个缺失窗口仍可能已发送，继续阻塞；不能以安装新代码替代旧运行证据。
- 显式 `outcome_unknown` 回执始终阻塞对应窗口。
- 多次执行、回执断号或 unknown 后仍有回执，均保守阻塞整个范围。

## 已证实的发送前持久回执协议

只有经核对实际部署代码保证“发送前先持久写入 VISUAL_REQUEST_DISPATCHED，丢失执行租约则停止发送”，且同一作业的运行监测实际读到该标记时，才使用本地维护入口 `media_catalog.visual_resume_scope.certify_dispatch_receipt_protocol`。

1. 确认旧执行进程已经退出，并用正规 `request_cancel` 取消作业。认证不负责终止进程。
2. 保存原始监测 JSONL 与 SHA256，记录部署/退出边界依据。监测包含 `at`、`jobId`、`job.status`、`counts[{status,error_code,n}]`。
3. 先在数据库副本验证。调用时传入 `db`、精确 `job_id`、`monitor_path`、`monitor_sha256` 和说明实证的 `deployment_note`。
4. 入口在同一即时事务内重新核对已取消、唯一已结束 attempt、连续回执、每条回执的 `provider_dispatched=1`；验证监测确属该作业且实际标记处于此次执行时间内。
5. 在独立 `visual_resume_certifications` 表追加不可覆盖的认证，保留监测原文、SHA、路径及说明，绑定全部 payload、attempt 和最终回执摘要。重复相同认证幂等；证据冲突拒绝覆盖。
6. 后续正规 preview/queue 读取该认证。无显式未知回执的缺失窗口可重排；显式未知仍阻塞。绑定数据变化使认证失效并阻塞整个范围。无需直接清除 unknown、改失败状态或补造回执。

认证是特定旧作业的本地审计恢复入口，不是通用“允许重试”开关。不能将一个作业的证据用于另一个作业。证据读取失败或不足时保留旧规则；不要自行编造监测文件。成功观察仍通过原 preview 复用，外发范围及费用沿用正常授权与队列规则。

视觉分析只发送抽样画面。本恢复不分析素材原声，也不改变成片音轨。
