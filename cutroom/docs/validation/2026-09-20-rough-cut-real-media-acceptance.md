## 1. 结论

原先用色块和“镜头 N”代替素材画面的实现不符合已确认的产品设计，2026-09-06 矩阵中基于该占位实现的“粗剪通过”结论在本次验收中正式撤回。

本次实现已通过粗剪真实素材与画面锁定专项验收：用户在锁定前能看到任务实际采用的图片或视频、完整顺序和真实切点，能先预览候选再确认替换，并能完成排序、播放头拆分、删除、撤销和重做。图片镜头不再显示无效裁剪控件；绑定视频片段的镜头保留入点/出点裁剪。任一镜头不可访问时，前端明确阻断且服务端重新核验；锁定请求还必须携带逐镜预览版本，服务端会重新比对文件版本并用 FFmpeg 在目标来源起点实际解码一帧，无帧、损坏帧或浏览器不支持的编码均拒绝锁定。

本报告不把当前遗留广告任务记作“最终成片端到端通过”：该任务没有 `packaging_plan`，任务资产只有 B-roll 图片，且已有 `render_and_qa` 作业为失败状态，不能在不伪造前置数据的情况下完成真实最终渲染。渲染适配层的照片全屏映射由自动化回归覆盖。

### 4.3 离线门禁

在独立副本中把第 1 镜头素材位置标为 `missing` 后：

- 主预览显示“镜头无法预览 / 素材文件当前不可访问”；
- 第 1 镜头缩略图区显示失败状态；
- “确认粗剪并锁定画面”禁用，并明确提示“第 1 镜头：素材文件当前不可访问。”；
- 恢复该副本的素材状态并刷新后，锁定按钮重新可用。

服务端绕过页面直接锁定的拒绝路径由 `tests.test_workbench_api` 覆盖。

### 4.4 真实视频与非零来源时间

由于真实任务的 91 个候选均为照片，另用本地生成的 180×320、5 秒 H.264 MP4 做不改业务账本的补充验收：

- 新增锁定门禁在来源时间 1.5 秒实际调用 FFmpeg 解出一帧；空输出或解码报错均按“素材无法解码”拒绝。
- Codex 内置真实浏览器通过本机 HTTP 加载该 MP4，跳转到 1.5 秒后返回 `currentTime=1.5`、`duration=5`、`readyState=4`、`videoWidth=180`、`videoHeight=320`，证明非零 seek 后已有可展示帧。
- 按 1.5–3.5 秒实际裁切后，ffprobe 返回 H.264、180×320、1.96 秒；与 API 将非零片段来源窗口独立于叙事时间投影、render-mix 按 `sourceStart/sourceEnd` 裁切的语义一致。
- 自动化另外覆盖：segment 20–30 秒、叙事时长 4 秒时预览解析为来源 20–24 秒；数字人 12–16 秒锚点解析为来源 12–16 秒；跨镜播放后编辑操作绑定新 `card_id`，候选视频显示原生控制条，浏览器加载失败立即停播并阻止锁定。

## 7. 已知边界

- 当前 91 个候选都是照片，因此真实业务任务截图仍只代表照片粗剪；视频浏览器解码和非零 seek 由本地合成 H.264 视频单独验收，不能冒充这 91 个候选中存在视频。
- 当前遗留任务不具备包装方案和配音资产，不能作为最终渲染样片。最终成片一致性仍应在具备完整包装与配音前置条件的新广告任务上单独验收。
- 粗剪播放器是浏览器端按锁定场景卡连续预览，不会在每次替换或排序后同步等待 FFmpeg 重渲染完整 rough-v1；最终渲染仍以锁定账本为唯一输入。
