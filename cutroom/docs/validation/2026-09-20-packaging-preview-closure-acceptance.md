# 剪辑工作台包装预览与素材检查闭环验收

验收日期：2026-09-21
分支：`codex/packaging-preview-closure-impl`
验收对象：包装方案试听/查看、真实短预览、观看后确认、个人模板、包装素材目录检查与正式渲染复用

## 1. 结论

剪辑工作台原包装阶段只有方案条目和“预览/确认”按钮语义，没有生成可播放的真实合成预览，也没有把用户实际看过的预览绑定到确认凭证；个人/扩展包装目录也缺少受控的新增、更新、丢失和损坏检查。

本次修复把包装阶段收口为一条可核验链路：包装方案绑定画面锁定和方案摘要，统一编译字幕、音色、BGM、音效、文字卡、贴纸、花字及 Logo/水印层；数字人和信息流广告都通过正式渲染路径生成最长 12 秒、540×960 的 H.264/AAC 真实预览。只有当前方案对应的预览处于 ready、文件签名仍有效且用户已观看时才允许确认。确认事件持久保存预览编号、观看时间和规范摘要，后续方案或画面变化会使旧预览失效。

独立审查后进一步收紧：广告正式成片与预览共同消费同一包装编译结果；预览规范身份同时绑定 manifest、包装文件、字幕源、广告分镜/时间表/配音输入；系统推荐方案在服务端不可变，只能克隆后修改。

目录检查只读扫描核心、团队扩展和个人包装目录，报告 added、updated、missing、invalid、unchanged；未知授权和路径逃逸文件永远不可选，也不会自动写入清单。

## 2. 用户闭环

```text
选择方案 → 单项试听/查看 → 必要时复制并替换/关闭 → 生成真实预览
→ 看完预览 → 确认方案 → 可选保存为个人模板 → 正式渲染
```

- 预览不是最终成片，使用低分辨率、短时长配置加速审核；正式渲染默认参数不变。
- stale、failed、missing 或文件签名变化的预览必须重新生成。
- 同一画面锁定与方案摘要的连续请求只保留一个规范预览产物和一个活动任务。
- 包装确认必须携带当前预览编号；CLI 与 Workbench API 均不能绕过。
- 个人模板是不可变快照，应用时复制为当前任务的新草稿，不直接修改历史模板。
- 系统推荐方案同样不可直接替换或关闭槽位；“从空白开始”和克隆后的自选方案才可编辑。

## 3. 安全与一致性

- 预览媒体只允许从 `runtime/workbench/cache/packaging-previews/` 受控目录解析。
- 媒体读取前核对任务归属、ready 状态、相对路径、扩展名和内容签名。
- Web 媒体端点要求本机会话认证，并支持 GET、HEAD 与单段 Range。
- 包装目录检查不返回绝对路径，不修改 manifest，也不把未知授权素材加入可选列表。
- 数字人预览沿用锁定字幕来源；广告预览复用已存在配音，不触发额外付费 TTS。
- 预览 worker 属于本地、非付费、重任务队列，与正式渲染共享全局重任务并发限制。

## 4. 渲染证据

- 数字人预览调用正式 `render-mix` 适配层，显式传入 draft 包装方案、输出画布、CRF 和时长上限。
- 信息流广告预览调用正式 `render-ad` 路径，转场前逐段裁切，复用已生成配音并消费统一包装层。
- 信息流广告正式成片重新校验当前授权和包装文件签名，并消费与预览相同的 SFX、文字卡、贴纸、花字和品牌字段。
- 真实 FFmpeg 测试产物为 H.264/AAC、540×960 竖屏 MP4，时长不超过请求上限。
- 未选择可选槽位时仍生成真实字幕预览，并在 coverage 中记录不适用或未启用原因。

## 6. 浏览器与兼容性证据

- 已合并粗剪真实素材分支 `e582166`，包装 UI 与粗剪 UI 在同一版 `app.mjs`、`styles.css` 上完成回归。
- 390px 窄屏真实 Chrome 用例验证 9:16 视频、当前槽位原生音频预览、保存模板、关闭可选槽位和确认按钮均可达，页面无横向溢出。
- 浏览器用例验证确认按钮初始禁用，视频播放到 90% 后调用当前预览的 `viewed` 接口并开放确认。
- 全量回归暴露的旧 v2 夹具伪音频已换成可解码音频；正式包装文件可读性校验没有放松。

## 7. 验收边界

本报告证明代码、受控 API/媒体路由、真实 FFmpeg 编解码样本、无头浏览器交互和全部自动化门禁通过。验收使用一次性测试任务与临时素材，不修改用户现有任务数据库，也没有把测试预览描述成已发布业务成片。首次使用真实业务任务时仍应人工比较三个推荐方案、最终成片与预览的一致性，并记录业务任务的预览 ID 与正式渲染快照。
