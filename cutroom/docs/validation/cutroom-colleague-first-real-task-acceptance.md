# 剪辑工作台普通同事首条真实任务验收单

状态：**待普通同事本人执行**。本文件用于安排和记录首条真实数字人混剪任务，不代表验收已经通过。

## 1. 验收目标

验证一名没有专业剪辑经验的普通同事，能在自己的 Windows 电脑上依靠剪辑工作台页面完成一条真实数字人混剪，并清楚知道当前阶段、缺什么、下一步做什么。

目标不是证明“按钮能点”，而是同时验证：

- 本机安装、登录自启和页面恢复可用；
- 本机硬盘或移动硬盘的真实素材能登记、扫描和用于任务；
- 四个人工门禁没有被自动流程绕过；
- 渲染、自动 QA、完整审片和七文件发布包能够闭环；
- 人工操作时间、总完成时间、返工点和技术中断都有记录。

## 2. 角色边界

| 角色 | 可以做什么 | 不应代替什么 |
| --- | --- | --- |
| 普通同事本人 | 全程操作页面，确认文案、镜头、包装和成片，记录理解困难与操作时间 | 不接触命令行、SQLite、模型 ID、音色 ID |
| 维护人员 | 安装软件、录入本机凭据、观察日志、记录技术故障 | 不代替普通同事点击门禁或填写“通过” |
| 部门负责人 | 最终审核业务内容和发布条件 | 不把自动 QA 当成人工审片 |

## 3. 验收输入

开始前准备一套真实、可发布或可内部验收的材料：

- [ ] 一条最终数字人口播 MP4；
- [ ] 与 MP4 口播完全一致的最终文案；
- [ ] 一个项目专属的主素材目录；
- [ ] 可选的通用补充素材目录；
- [ ] 最近 24 小时检测成功的文案策划模型；
- [ ] 足够的输出磁盘空间；
- [ ] 素材版权、隐私和业务事实已由负责人确认。

首次验收只跑“数字人混剪”。项目宣传片仍未开放；信息流广告在数字人首片稳定后单独安排。

## 9. 通过标准

同时满足以下条件才可标记“普通同事首条真实任务通过”：

1. 普通同事本人在自己的电脑完成一条真实数字人任务；
2. 四个人工门禁全部由本人操作且可追溯；
3. 技术中断为 0，或能只使用页面提供的安全恢复继续；
4. 自动 QA 无阻断项，普通同事完成整片观看并作出真实判断；
5. 七文件发布包完整；
6. 人工操作时间、总完成时间和所有返工点已记录；
7. 普通同事能在不依赖维护人员代操作的情况下说明“当前在哪一步、下一步做什么”。

任一项未满足，状态填写“未通过”或“有条件通过”，并记录具体阻断，不允许用自动测试替代人工签收。
