# 视频生产系统分期开发路线

> **For agentic workers:** 每个阶段单独形成详细实施计划并独立验收；不得在 P0 未通过真实 10GB 素材验证前并行铺开 P1—P3。

**Goal:** 按普通办公电脑、单机单重任务、渐进式建库的约束，把定稿工作流逐步实现为团队成员可使用的视频生产系统。

**Architecture:** 先用 Python 标准库建立独立、可测试的 SQLite 素材数据底座，再通过 JSON/CLI 适配现有 TypeScript `plan / compile / render-mix`。每阶段都产生可独立使用的软件闭环；视频脚本写作 Skill 只通过稳定契约接入，不绑定具体 Skill 名称或模型。

**Tech Stack:** Python 3.11 标准库、SQLite、`unittest`、FFmpeg/ffprobe、现有 TypeScript 5.7、ts-node 和 FFmpeg 渲染脚本。

## 阶段路线

| 阶段 | 可独立交付的闭环 | 主要能力 | 进入下一阶段的门禁 |
| --- | --- | --- | --- |
| P0 数据底座 | 10—50GB目录可扫描、索引、搜索和断点恢复 | 素材库注册、SQLite迁移、快速指纹、技术探测、备份恢复、单重任务锁、磁盘预估、状态摘要 | 真实大目录测试通过；换盘符可恢复；NAS离线不误删；数据库能从备份恢复 |
| P1 可视与可选 | 不打开大原片即可浏览并确定候选素材 | 缩略图、接触表、按需代理、音频预览、VAD/粗转写、三级质量结论、隐私提示、用户指定素材 | 项目和数字人任务均能形成可人工确认候选池；代理与原片时间码一致 |
| P2 剪辑组装与交付 | 两类真实任务从素材ID生成可发布成片 | 场景卡片、B-roll混剪、累积字幕、音频策略、包装资产、局部重跑、质检、发布包 | 项目和数字人各完成真实端到端样片；BGM不压人声；四个人工门禁可追溯 |
| P3 智能深化 | 推荐、脚本和规则能够从真实反馈持续改进 | OCR/语义匹配、重复检测、视频脚本写作适配器、规则版本、效率校准 | 30分钟标准任务和2小时4条目标通过普通同事实测；无技术性反复返工 |

## 固定边界

- 同一时间只执行一个识别、代理生成或渲染重任务；轻量浏览和文案编辑可继续。
- 原片只读，不上传给 Agent；模型只读取摘要、缩略图、代理、标签和时间码。
- 素材、分析、任务状态和人工决定以 SQLite 为主账本；JSON 是下游导出物。
- 新任务默认最新规则，原任务锁定创建时的规则和资产版本。
- 当前三平台共用同一份 9:16 成片，不做平台派生版本和自动发布。
- P0 不实现界面、视觉识别、自动分镜、完整代理、视频脚本写作 Skill 或剪映原生工程。
