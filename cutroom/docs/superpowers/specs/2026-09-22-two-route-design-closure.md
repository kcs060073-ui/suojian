# 剪辑工作台数字人和信息流路线设计收口

**日期：** 2026-09-22
**状态：** 软件实现与自动化验证已完成，待合并推送
**依据：** `2026-09-05-colleague-video-workbench-design.md`、2026-09-20 原始设计实现偏差审计，以及当前 `main` 实现

## 1. 目标

在不重写现有本地工作台、SQLite 主账本和后台单重任务队列的前提下，补齐数字人混剪与信息流广告两条路线尚未达到原始设计的功能，使两条路线都能从任务创建进入统一工作流，经过自动处理与四道人工门禁，最终形成可追溯发布包或可编辑交付包。

本轮完成代码、界面、自动化测试、数据迁移和操作文档。真人试用、普通同事现场测试和真实现场素材验收不在本轮完成口径中，不能用自动化测试替代或宣称已经通过。

## 2. 范围

### 2.1 本轮包含

- 数字人混剪路线的剩余工作台、QA、后台队列和交付差距。
- 信息流广告路线与统一工作流、门禁、QA 和交付规则的兼容收口。
- 两条路线共用的任务搜索筛选、预检信息、镜头素材索引、AI 推荐纠正、暂停与 ETA、发布准备和可编辑交付。
- 已完成的真实粗剪、包装预览、候选版本、完整审片、分类返工和发布候选绑定的回归验证。

### 2.2 本轮不包含

- 项目宣传路线的新建、预检、工作区、渲染或发布能力；界面继续明确显示“后续开放”。
- 真人试用、普通同事无指导测试、真实拍摄现场验收或真实项目纵切。
- 自动登录或发布到抖音、视频号、小红书等外部平台。
- 剪映原生工程、任意多轨编辑器、云协作或复杂版权审批。
- 新 Beta 标签、GitHub Release 或安装包发布；本轮只合并并推送 `main`。

## 3. 方案选择

采用“现有架构增量收口”方案：保留浏览器工作台、`workbench/api.py`、`media_catalog` 领域模块、SQLite 主账本和后台 worker，在既有契约上增加缺失字段和动作。不会引入第二套任务状态机，也不会为两条路线各自复制一套 UI。

没有采用只修数字人公共页面的最小方案，因为信息流路线仍会绕开统一质量与交付规则；也不采用通用流程引擎重写，因为会扩大迁移和回归风险。

## 4. 工作台收口

### 4.1 任务中心

任务列表增加本地搜索、路线筛选、运行状态筛选和稳定排序。搜索覆盖任务标题和任务 ID；路线仅显示数字人混剪、信息流广告以及已有历史任务的只读值。筛选只改变展示，不修改任务状态。

任务卡和列表继续读取同一 API 数据，不创建前端影子状态。打开任务后仍以 SQLite 中的当前阶段、运行状态、门禁和下一动作作为唯一依据。

### 4.2 创建与预检

两条路线的预检统一展示：

- 强制输入、素材目录在线状态和变化状态；
- 当前重任务与等待数量；
- 有依据的机器耗时范围、人工操作时间、预计新增空间；
- 预计 API 费用、不包含项和未知项；
- 四道人工作业确认；
- 真实性、隐私和授权提醒。

未知值保持 `null/unknown`，不能显示为零。预检是只读快照，不预留队列槽位、不批准费用，也不触发转写、TTS、模型生成或渲染。

### 4.3 镜头素材索引

镜头素材页在现有目录管理基础上增加资产索引视图，可按目录、媒体类型、在线状态、授权状态和关键词筛选。每项显示预览、来源目录、相对路径、媒体摘要、授权和在线状态。

任务工作区的候选素材只来自任务冻结的素材范围。目录变化先显示影响，不得静默替换已经确认的镜头。离线素材保留索引，恢复后继续通过身份和指纹重连。

### 4.4 AI 推荐纠正

数字人和信息流路线的推荐结果都提供“拒绝”“纠正要求”“重新推荐当前场景”。操作必须记录理由、目标场景、原推荐与新候选，并在采用前展示来源和影响范围。

AI 始终生成候选，不直接覆盖当前粗剪或已经确认的人工决定。付费或可能付费的重新生成继续走显式确认和现有 provider request 账本。

## 5. 队列、暂停和预计时间

后台继续保持单重任务串行。队列公开字段补齐：排队序号、当前进度、预计开始时间、预计剩余时间、估算依据和观测时间。

ETA 来自同类已完成作业或当前作业进度；没有有效样本时返回未知，不编造精确时间。

“暂停”采用安全检查点语义：

- 排队作业可立即进入 `paused`；
- 运行作业记录暂停请求，在当前不可分割步骤结束后进入 `paused`；
- 恢复时从最后一致检查点重新入队，不重复已经确认的付费调用；
- 取消与暂停保持不同状态，取消不能由恢复动作重新启动。

浏览器关闭不影响后台作业；服务重启后从账本恢复排队、暂停、运行中断和检查点状态。

## 6. QA 深检

在现有编码、比例、黑帧、冻结、静音、削波、依赖、重复、包装和隐私检查基础上补齐：

- 字幕文件存在、解析有效、时间范围合法、与成片时长一致；
- 字幕安全区、最大行数和异常断句；
- 综合响度、True Peak 或可获得的峰值，以及人声/BGM 策略检查；
- 当前素材文件与冻结指纹的一致性；
- 每个实际使用素材的来源、范围归属和授权状态；
- QA 输入、候选版本、包装快照和渲染依赖一致。

不能可靠测量的项目返回明确的 `unknown` 或阻断原因，不以“通过”代替未检查。阻断项仍禁止进入完整审片确认和发布包生成。

## 7. 发布准备与交付

发布页补齐以下交互：

- 选择系统生成的封面候选；
- 指定外部封面文件，或显式选择“待补封面”；
- 编辑和保存发布标签；
- 展示当前候选版本、QA、完整审片和发布包绑定关系；
- 选择标准发布包或可编辑交付包。

标准发布包至少包含最终 MP4、选中封面或待补标记、发布文字、发布检查、QA 报告和版本清单。

可编辑交付包在标准发布包之外包含：

- 可获得的无最终包装基础视频；
- 人声、BGM、音效等可获得的分轨音频；
- ASS/SRT 字幕及字幕元数据；
- 素材时间码与来源清单。

若某一可编辑组成项在当前路线不可产生，清单必须记录 `not_available` 和原因，不能生成伪文件。所有包通过临时目录组装并原子替换，失败时不留下看似完成的包。

## 8. 两条路线的统一规则

数字人混剪和信息流广告共用十二步主链、四道人工门禁、候选版本、QA、完整审片和发布规则。路线差异只保留在输入、转写/TTS、分镜和渲染适配器中。

- 数字人口播主轴不得在粗剪中被切断或重排。
- 信息流广告允许 TTS 和句级配片，但必须冻结所选音色、文案、素材范围和模型配置。
- 两条路线的发布包都只能绑定当前、QA 通过且完整审片确认的候选版本。
- 项目宣传不加入路线适配分支，不因为公共代码变化而变为可创建状态。

## 9. 错误与恢复

新增动作继续返回稳定业务错误码和可执行下一步，不把绝对路径、命令行、密钥或底层异常直接显示给用户。

重点覆盖目录离线、素材变化、空间不足、字幕缺失、响度无法测量、授权不明、暂停请求失败、服务重启和可编辑包缺少组成项。恢复动作必须幂等，并保留既有版本、人工决定和 provider request 记录。

## 10. 数据兼容

新增字段通过向前兼容迁移加入；旧任务和旧发布记录可读取。历史记录缺少新字段时显示未知或不可用，不回填虚构数据。API 只新增字段或动作，保留现有前端与 Agent MCP 使用的字段语义。
