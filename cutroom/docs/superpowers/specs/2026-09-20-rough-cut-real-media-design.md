# CUTROOM 粗剪真实素材预览与编辑闭环设计

状态：待 Peter 书面复核  
日期：2026-09-20  
依据：[同事视频工作台设计](./2026-09-05-colleague-video-workbench-design.md)

## 1. 目标

恢复最初产品设计中的粗剪能力：用户在画面锁定前必须看见任务实际采用的图片或视频、完整镜头顺序和真实切点，并能在同一工作区完成替换、排序、入出点调整、播放头拆分、删除、撤销和重做。

本设计修正当前正式页面把 V4 演示色块误当作粗剪预览的偏差。文件名、检索词和系统建议只能辅助判断，不能替代真实画面。

## 2. 成功标准

1. 主预览区显示当前镜头的真实图片或可播放视频，不再显示渐变色块。
2. 时间线每个镜头显示真实缩略图、镜头序号和时间范围，排序结果与后端场景卡一致。
3. 用户可从头连续播放粗剪；播放器按场景卡顺序切换素材，并维护唯一的全局播放头。
4. 右侧替换候选以可视化卡片展示；选择候选只预览，确认后才替换当前镜头。
5. 排序、入出点裁剪、播放头拆分、删除、撤销和重做全部连接现有持久化粗剪 API。
6. 图片或视频离线、路径越界、类型不支持或无法加载时，页面明确指出具体镜头，服务端拒绝画面锁定。
7. 原始素材保持只读；浏览器不能通过 URL、查询参数或响应内容获得任意本机绝对路径。
8. 当前真实任务的 9 个镜头能够逐镜预览、连续播放、替换和排序，再进入画面锁定。

## 3. 方案选择

采用“代理优先、受控源文件兜底、浏览器连续粗剪播放器”。

- 不采用只显示当前素材的最小修补，因为它不能让用户判断整体顺序和节奏。
- 不采用每次编辑后同步调用 FFmpeg 重渲染完整 rough-v1，因为排序、裁剪或替换后的等待会破坏粗剪交互。
- 浏览器根据场景卡和全局播放头连续切换真实素材。图片按镜头时长停留；视频从来源窗口播放；一个镜头结束后进入下一镜头。
- 已有缩略图和视频代理优先使用。缓存不存在时，图片和视频可通过任务受控的源文件流立即预览；缓存生成后自动改用派生产物。源文件兜底只供本机浏览器，不提供给通用模型。

## 4. 架构与职责

### 4.1 素材解析层

新增聚焦的粗剪媒体解析模块，输入 `task_id`、`asset_id` 和用途，输出经过校验的本地文件与媒体描述。

解析必须同时满足：

- 任务存在。
- 素材是当前场景卡使用的素材，或属于当前任务激活且在线的主素材/通用素材范围。
- `asset_locations.state` 为 `available`。
- 解析后的真实路径仍位于登记素材库根目录内。
- 用途只允许 `thumbnail` 或 `preview`。
- 媒体类型只允许 `image` 或 `video`。

`thumbnail` 优先读取 `preview_cache.thumbnail`；没有缓存时安全使用受控源文件，由浏览器按缩略图尺寸展示。`preview` 对视频优先读取 `preview_cache.proxy`，否则使用受控源视频并支持 HTTP Range；图片优先缩略图，没有缩略图时使用受控源图。

响应不得接收或回显任意文件路径。所有访问以不可猜测也不可越权的素材 ID 为入口，并在每次请求时重新核对任务范围和在线状态。

### 4.2 工作台媒体接口

新增经过本机会话认证的只读接口：

```text
GET|HEAD /api/tasks/{task_id}/rough-media/{asset_id}/thumbnail
GET|HEAD /api/tasks/{task_id}/rough-media/{asset_id}/preview
```

接口复用现有 `_send_media_file()` 的 Range、MIME、`no-store`、`nosniff` 和客户端断开处理。典型错误使用稳定代码：

- `ROUGH_MEDIA_NOT_ALLOWED`：素材不在本任务允许范围。
- `ROUGH_MEDIA_OFFLINE`：登记位置离线或文件不存在。
- `ROUGH_MEDIA_UNSUPPORTED`：素材类型不适合粗剪预览。
- `ROUGH_MEDIA_CHANGED`：缓存签名与当前源文件不一致。

### 4.3 任务详情投影

`sceneCards` 和 `eligibleAssets` 增加浏览器所需的媒体描述，但不包含绝对路径：

```json
{
  "media_kind": "image",
  "thumbnail_url": "/api/tasks/.../thumbnail",
  "preview_url": "/api/tasks/.../preview",
  "preview_delivery": "cache|source",
  "preview_available": true,
  "preview_problem": null
}
```

场景卡保留叙事时间 `narrative_start/end`，同时明确来源窗口 `enter_tc/exit_tc`。前端不得从文件名猜测媒体类型、时间范围或可用性。

### 4.4 浏览器粗剪播放器

播放器使用场景卡列表作为 rough-v1 描述，并维护：

- 当前镜头 ID。
- 全局播放头秒数。
- 播放/暂停状态。
- 已加载媒体状态和错误状态。

播放规则：

- 图片在对应叙事区间内持续显示。
- 视频从 `enter_tc` 开始播放；没有显式来源窗口的数字人口播使用对应叙事时间定位。
- 来源视频短于镜头区间时按现有渲染规则循环或保持末帧；具体行为由任务媒体描述给出，前端不自行猜测。
- 全局播放头到达当前镜头末尾时自动选择并播放下一镜头。
- 点击时间线镜头或拖动播放头会立即切换实际媒体，并更新右侧对象面板。
- 媒体加载失败时停止自动前进，显示镜头编号、原因和恢复入口，不以占位色块伪装成功。

### 4.5 时间线与编辑动作

时间线卡片显示缩略图、镜头序号、叙事时间、素材类型和选中状态。

排序同时提供拖放和键盘可达的“左移/右移”操作。提交 `reorder` 前显示影响预览；服务端仍要求当前卡片恰好出现一次，并保持数字人口播声音主轴连续。

裁剪面板显示来源入点、出点和允许范围。修改提交现有 `trim` 动作；前端预校验只负责及时提示，服务端规则仍是最终权威。

拆分按钮使用全局播放头，而不是镜头中点。播放头必须严格位于可编辑画面段内部；数字人口播主轴不可拆分。

删除只允许 B-roll 或信息卡。替换只影响当前镜头。所有动作先调用影响预览，再由用户确认应用，并继续复用现有 undo/redo 事务和锁定失效逻辑。

### 4.6 可视化替换候选

右侧候选区从文件名下拉框改为素材卡片网格。每张卡片包含：

- 真实缩略图。
- 文件名或相对路径。
- 图片/视频类型。
- 主素材或通用补充来源。
- 预览失败状态。

点击卡片只在主预览区查看候选，不修改场景卡；点击“替换当前镜头”后才调用影响预览和 `replace`。候选预览结束可返回当前已采用素材。

### 4.7 画面锁定门禁

前端只有在所有场景卡都具有可解析且支持的画面素材时才启用“确认粗剪并锁定画面”。服务端 `picture/lock` 在事务前重新核验同一条件，防止绕过页面直接调用。

锁定不要求系统代替用户观看，也不伪造“已确认”；最终点击仍由用户完成。锁定后修改继续沿用现有影响令牌和后续阶段失效规则。

## 5. 文件边界

- `media_catalog/rough_media.py`：任务范围、素材位置、缓存与源文件解析；不处理 HTTP。
- `workbench/routes.py`：认证、路由、HTTP Range 和媒体响应。
- `workbench/api.py`：给场景卡与候选素材补媒体描述；画面锁定前调用可预览性校验。
- `web-ui/public/rough-preview.mjs`：纯播放器时间模型、场景定位、来源时间映射和排序辅助函数。
- `web-ui/public/scene-editor.mjs`：保持编辑命令构造与数值校验。
- `web-ui/public/app.mjs`：DOM 渲染、媒体事件、候选预览和提交影响确认。
- `web-ui/public/styles.css`：真实媒体舞台、播放头、时间线和候选卡片布局。
- `tests/test_rough_media.py`：解析权限、缓存、离线、越界和源文件变化。
- `tests/test_workbench_server.py`：认证、MIME、HEAD、Range 和错误响应。
- `tests/workbench-ui.test.mjs`：播放时间模型、排序、裁剪、真实播放头拆分和锁定门禁。
- `tests/workbench-layout.test.mjs`：主预览、时间线和候选区的代表视口检查。

## 6. 安全与失败处理

- 原始素材只读，所有预览缓存均为可重建派生文件。
- 请求永远不能携带本机路径；路径从 SQLite 任务范围反向解析。
- 符号链接、`..`、库根目录逃逸和任务外素材全部拒绝。
- 图片与视频 MIME 必须来自允许清单；未知格式不以内联方式发送。
- 缓存缺失不是成功占位：允许安全源文件兜底时返回真实媒体，否则返回明确错误。
- 素材在页面打开后离线或变化时，下次请求及画面锁定都必须失败并提示重新连接或扫描。
- 任何媒体错误都不能自动替换素材、跳过镜头或静默锁定。

## 7. 测试与验收

### 7.1 自动测试

按 TDD 顺序覆盖：

1. 当前任务采用的图片能通过认证接口读取，任务外图片返回 403/404 且不泄露路径。
2. 视频 Range 返回正确 `206`、`Content-Range` 和字节内容；HEAD 不返回正文。
3. 缩略图/代理存在时优先缓存；缓存缺失时只在允许的本机源文件上兜底。
4. 离线位置、源文件变化、越界符号链接和不支持类型均返回稳定错误。
5. 场景详情和候选素材都提供无绝对路径的媒体描述。
6. 全局播放头能定位正确场景和来源时间；图片、视频、数字人口播分别覆盖。
7. 排序保持卡片全集唯一，裁剪边界合法，拆分使用当前播放头。
8. 任一场景不可预览时前后端都拒绝画面锁定。
9. 现有撤销、重做、锁定后失效和渲染适配测试保持通过。

### 7.2 真实任务验收

使用当前 9 镜头、91 张候选素材的真实任务：

1. 从第一镜播放到最后一镜，逐镜看到当前采用的真实画面。
2. 时间线缩略图与主预览、右侧文件名一致。
3. 预览三个替换候选，确认前数据库不变化；确认后只替换当前镜头。
4. 调整至少两个镜头顺序，刷新页面后顺序保持。
5. 对可编辑镜头调整入出点，并在非中点播放头拆分；刷新和撤销/重做后结果正确。
6. 模拟一个素材离线，页面指出具体镜头且禁止锁定；恢复后重新可用。
7. 画面锁定后执行真实渲染，成片镜头使用和顺序与锁定粗剪一致。

## 8. 非目标

- 不建设自由多轨编辑器。
- 不允许重排或切断数字人口播声音主轴。
- 不在粗剪时间线编辑字幕、BGM、包装或复杂动画。
- 不把原始大视频上传给通用模型。
- 不以每次编辑都重新渲染完整视频作为交互前提。
- 不修改或覆盖用户原始素材。

## 9. 交付门禁

在自动测试、真实任务逐镜视觉验收和“锁定粗剪与最终渲染一致”全部通过前，不得再把粗剪页面描述为“可确认的代理预览”，也不得引导用户点击画面锁定。
