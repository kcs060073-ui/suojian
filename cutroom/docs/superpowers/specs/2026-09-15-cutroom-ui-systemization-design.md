# 剪辑工作台全局 UI 归一化设计

日期：2026-09-15
状态：已由 Peter 确认方案 A，待文档复核
目标版本：v0.9.0-beta.3

## 1. 背景与目标

剪辑工作台已具备任务中心、任务创建、任务详情、镜头素材、包装素材、AI 服务连接、存储与缓存等完整工作台页面，但不同页面在信息层级、卡片密度、表单标签、状态反馈、按钮优先级和响应式行为上仍不够统一。豆包配音接入过程中也暴露出凭据字段过多、保存成功不明确、失败状态长期残留和普通用户看到内部 ID 等问题。

本次采用“保留现有暖灰品牌语言、系统化归置”的方案 A：统一全应用设计令牌、公共组件和交互反馈，不重写业务流程、不更换前端技术栈、不改变任务与渲染数据语义。在此基础上完成豆包凭据精简，并把本版本作为 Beta 3 发布。

本设计覆盖 `2026-09-14-doubao-tts-voice-selection-design.md` 中关于豆包合成鉴权、设置页字段和同事首次配置的旧说明；音色目录、任务级选择、任务快照冻结和历史兼容等其余设计继续有效。

成功标准：

1. 七类页面使用一致的标题、卡片、表单、按钮、状态、空状态和反馈模式。
2. 豆包普通配置只要求新版 API Key、Access Key ID、Secret Access Key 和服务版本；AppID/Access Token 仅作为折叠的旧版兼容项。
3. 保存、检测、刷新等异步操作有明确的处理中、成功和失败状态，不能只依赖短暂 Toast。
4. 豆包普通流程不显示模型 ID、音色 ID、Resource ID、Cluster 或固定接口地址。
5. 375、768、1024、1440、1920px 宽度下无非预期横向滚动，主要操作可完成。
6. 现有历史配置、任务快照、渲染管线和旧版凭据仍可读取与执行。

## 2. 设计原则

### 2.1 保留识别度

延续现有暖灰背景、浅色面板和橙色强调，不切换为新的青色或蓝色品牌。橙色只用于当前步骤、重要提醒和关键强调；绿色表示成功，蓝色表示信息或处理中，红色表示失败或危险操作。

### 2.2 业务优先于技术字段

页面展示用户要完成的动作和可理解的状态。内部协议、模型 ID、音色 ID、Resource ID、Cluster、固定接口地址由预设和后端映射，不进入豆包普通操作路径。高级兼容供应商仍保留必要的手工字段，并与普通豆包流程明确分开。

### 2.3 状态必须可见且可恢复

异步操作先显示处理中并禁用重复提交，完成后同时更新页面内持久状态和简短 Toast。失败信息靠近相关区域，给出下一步操作；成功重试必须清除旧错误。页面刷新后仍能从后端状态恢复关键结果。

### 2.4 渐进披露

普通用户只看到完成任务所需的信息。旧版兼容配置、技术细节、危险操作和低频说明放入折叠区域或次级操作，不与主流程并列。

### 2.5 本地、安全、低依赖

不引入新的前端框架、远程字体、图标 CDN 或外部运行时。继续使用原生 HTML、CSS、JavaScript 和项目内 SVG。所有密钥仍只写入 Windows 凭据管理器，不进入 SQLite、页面状态、日志、ZIP 或 GitHub。

## 3. 信息架构与页面壳

保留现有三栏桌面结构：

- 一级导航：任务、镜头素材、包装素材、设置。
- 模块导航：当前模块的快速入口、分类或最近任务。
- 内容区：当前页面的标题、状态、主操作和内容。

顶部栏保留剪辑工作台品牌、本机工作流状态、重任务状态、使用手册和主题切换。状态控件在窄屏按优先级收敛，不能挤压主要内容。

响应式规则：

- 1440px 及以上：完整三栏，内容区使用统一最大阅读宽度和弹性留白。
- 1024–1439px：一级导航可折叠，模块导航保持可用，卡片和表单双列按空间收缩。
- 768–1023px：模块导航收敛为紧凑区域，主要表单和详情改为单列。
- 375–767px：一级导航改为可横向浏览的紧凑导航；内容、卡片、表单和操作栏单列；主要按钮全宽或成组排列。
- 看板和数据表允许在容器内部有意横向滚动，但页面本身不得产生横向滚动。

## 4. 设计系统

### 4.1 设计令牌

在现有 CSS 变量基础上整理语义令牌，不在组件中散落用途不明的颜色和尺寸：

- 颜色：background、shell、panel、soft、text、muted、border、accent、success、info、danger 及其弱背景。
- 字体：12、14、16、20、28px；正文行高不低于 1.5。
- 间距：4、8、12、16、24、32px。
- 圆角：8、10、12、14px，按控件、卡片、容器三个层级使用。
- 控件高度：普通输入和按钮至少 44px；紧凑图标按钮至少 40px，并保留可访问名称。
- 动效：只使用 150–200ms 的颜色、透明度和轻微位移过渡；遵守 `prefers-reduced-motion`。

### 4.2 公共组件

统一并复用以下视觉和行为模式：

- 页面标题：标题、说明、状态或主操作位置固定。
- Section Card：标题、辅助说明、内容和操作区结构一致。
- Form Section：显示真实标签、辅助文字、字段错误和分组说明。
- Button：primary、secondary、quiet、danger 四级；同一区域最多一个 primary。
- Status Badge：success、processing、warning、error、neutral，不能只靠颜色区分。
- Inline Feedback：持久显示保存、检测、刷新结果，并使用 `role=status` 或合适的 `aria-live`。
- Empty State：解释当前为空的原因，并提供一个明确下一步。
- Action Row：主要操作靠近工作区末尾；危险操作与主要操作分离。

## 5. 页面级设计

### 5.1 任务中心

- 统一看板卡片和列表行的标题、元数据、状态和下一步动作。
- 看板列使用一致的间距和空状态，卡片点击态与按钮操作态区分。
- 视图切换、筛选和新建任务进入同一页头操作区。
- 当前任务、运行中、已完成、阻塞使用统一状态徽标。

### 5.2 新建任务

- 保留现有步骤和预检逻辑，统一步骤条的当前、完成、阻塞状态。
- 每一步只突出当前需要完成的字段，说明文字紧跟相关控件。
- 路线卡、素材选择、模型选择和音色选择使用一致的选择状态。
- 预检结果按“通过、提醒、阻塞”分组，阻塞项提供返回修改入口。

### 5.3 任务详情

- 顶部集中展示任务名称、路线、当前阶段和运行状态。
- 流程步骤使用同一状态语言，当前步骤突出但不依赖颜色。
- “下一步”卡片优先于历史信息；失败时提供重试或返回设置的恢复动作。
- 运行日志和技术详情保持次级，不挤占普通用户主视图。

### 5.4 镜头素材

- 搜索、检查更新、添加目录组成统一工具栏。
- 目录卡片统一显示用途、位置、连接状态、最近扫描和素材数量。
- 本机、移动硬盘和不可用目录使用可读状态，不直接暴露底层兼容字段。
- 扫描操作显示处理中、防重复点击和完成结果。

### 5.5 包装素材

- 分类卡片使用一致的图标、标题、数量和状态。
- 详情面板与列表保持稳定空间，避免内容切换造成大幅布局跳动。
- 推荐来源、许可说明和本地素材位置属于辅助信息，与主要选择操作分层。

### 5.6 AI 服务连接

供应商账号和模型配置分成两个清晰层级：账号负责鉴权与目录，模型配置负责业务能力和常用选择。

豆包账号普通表单显示：

1. 豆包 API Key：新版 V3 合成、试听和连接测试所需。
2. Access Key ID：自动读取音色目录所需。
3. Secret Access Key：自动读取音色目录所需。
4. 配音服务版本：选择语音合成 1.0 或 2.0，并由程序映射资源标识。

以下字段不出现在普通主流程：

- AppID、Access Token：保留在默认折叠的“旧版兼容设置”中；已有值不删除、不回显。
- API 请求地址：豆包预设固定使用官方地址，不要求普通用户编辑。
- Resource ID、Cluster：内部映射。
- 精确模型 ID、音色 ID、高级兼容音色 ID：豆包模型配置完全移除。

账号卡片持久显示三个事实：合成服务是否已连接、音色目录是否已连接、当前服务版本及可选音色数量。编辑凭据、重新检测、刷新音色和删除账号按使用频率分级，删除与主操作分开。

“保存并检测”按顺序执行：

1. 保存凭据。
2. 使用关联豆包配音配置执行真实短文本检测；尚无配置时只验证可验证部分，并明确提示需要创建配置后完成合成检测。
3. 使用 AK/SK 刷新音色目录。
4. 刷新账号和配音配置状态，清除已经恢复的旧错误。
5. 页面内显示“合成已连接”“音色目录已连接”“N 个可选音色”和检测时间；任一步失败时保留前面已经成功的结果。

为避免意外计费，按钮说明明确“连接检测会合成一条极短测试语音”。同一账号关联多个配音配置时只测试当前默认或用户明确选择的配置，不批量合成全部音色。

豆包配音配置表单只显示账号、配置名称、服务版本摘要、可搜索音色选择、试听和设为常用音色。OpenAI 兼容等高级 TTS 仍保留模型与音色 ID，但界面明确标记“高级兼容”。

### 5.7 存储与缓存

- 只读容量与路径信息、可修改目录设置、缓存清理三个层级分区。
- 缓存清理继续使用预览影响范围再确认的门禁。
- 危险操作使用 danger 样式、明确影响范围，不与普通保存按钮相邻。

## 6. 交互与错误处理

所有异步按钮在请求期间：

- 禁用重复点击并设置 `aria-busy=true`。
- 文案改为“正在保存…”“正在检测…”或“正在刷新…”。
- 保持按钮宽度和布局稳定，避免闪动。

成功时：

- 更新页面内持久状态。
- 清除同一对象的旧错误。
- 显示简短成功 Toast，辅助而不是替代持久结果。

失败时：

- 保留用户输入和已成功步骤。
- 在对应卡片或字段附近显示安全中文错误。
- 提供明确恢复动作，例如重新检测、刷新目录、打开火山服务页或检查凭据。
- 不显示完整上游响应、请求头或任何凭据。

删除账号、清理缓存等破坏性操作继续要求确认。不能通过颜色、悬停或 Toast 单独传达关键状态。

## 7. 可访问性

- 标题层级连续，每页只有一个主标题。
- 输入控件有真实标签，帮助文字通过可访问关系关联。
- 键盘焦点可见，导航、表单和主要操作可用键盘完成。
- 正文与背景对比度达到 4.5:1；状态同时使用文字或图标。
- 动态状态使用克制的 `aria-live`，避免多个徽标同时播报。
- 图标按钮具有 `aria-label`；装饰 SVG 使用 `aria-hidden=true`。
- 不禁用浏览器缩放；窄屏触控目标保持可点击尺寸。

## 8. 数据、安全与兼容

- 不修改任务、素材、渲染或配音快照的数据语义。
- 不删除旧豆包 AppID/Access Token、旧配置、历史任务或历史音色。
- 新版 API Key、Secret Access Key 和 Access Token 继续保存在同一条版本化 Windows 凭据记录中；页面和接口只返回“是否已配置”。
- Access Key ID、AppID、服务版本等非密钥配置可留在 SQLite；普通界面只显示必要的可读名称。
- 同事电脑的凭据不随 GitHub、ZIP 或数据库复制；换电脑或换 Windows 用户仍需管理员录入一次。

## 9. 技术实现边界

- 保留原生 HTML/CSS/JavaScript 架构。
- 优先整理 `web-ui/public/styles.css` 中的令牌和公共组件，再对 `index.html` 与 `app.mjs` 做最小结构调整。
- 后端只增加支持“保存并检测”状态编排所必需的接口行为，不建立新的远程服务或前端状态框架。
- 不引入在线字体、图标库、CSS 框架、动画库或前端打包器。
- 现有布局测试和 API 测试作为回归基础，不删除以绕过失败。

## 10. 测试与验收

实施使用测试驱动开发。每项行为先增加失败测试，再写最小实现。

自动化门禁至少覆盖：

1. 豆包普通表单只显示三项凭据和服务版本；旧版字段位于折叠区。
2. 豆包配音配置不显示自由模型 ID 和音色 ID；高级兼容 TTS 仍可使用必要字段。
3. 保存并检测的步骤、按钮 busy/disabled 状态、持久成功状态和分步失败结果。
4. 成功重试清除旧错误，目录失败不删除上次成功音色。
5. 导航、按钮、表单、状态、空状态和危险操作的公共结构。
6. 375、768、1024、1440、1920px 的页面宽度、侧栏、表单列数和横向溢出。
7. 键盘焦点、标签、`aria-busy`、`aria-live`、图标可访问名称和减少动态效果。
8. 现有任务创建、素材管理、配音快照、渲染和升级兼容测试全部通过。

真实验收至少覆盖：

1. 使用当前新版 API Key 和 AK/SK 保存并检测。
2. 音色目录返回可读名称和正确数量。
3. 选择并试听至少两个不同音色。
4. 创建一条信息流广告任务并核对冻结音色。
5. 刷新页面后成功状态仍正确，旧错误不再出现。
6. 在独立目录解压 Beta 3，复制数据库副本并完成安装、启动和页面访问。

## 11. 发布

完成代码审查和全部门禁后：

1. 更新 Beta 3 版本号、README、使用手册、升级说明和 Release Notes。
2. 构建 `剪辑工作台-v0.9.0-beta.3-windows-x64.zip`，生成并核验 SHA256。
3. 检查 ZIP 不含 SQLite、`.env`、Windows 凭据、API Key、AK/SK、Token、缓存或用户素材。
4. 在隔离目录执行安装与启动冒烟测试。
5. 将实现提交到 `codex/tts-voice-refresh-fix`，推送远端并按仓库现行流程合入主分支。
6. 创建 `v0.9.0-beta.3` Git 标签和 GitHub Release，上传 ZIP 并提供下载链接。

若真实服务、GitHub 权限或外部网络失败，必须报告具体阻塞，不以未验证状态宣称发布完成。

## 12. 非目标

- 不重写任务、素材、渲染或模型配置业务流程。
- 不引入团队云端密钥托管。
- 不自动删除重复或旧版配音配置。
- 不自动替用户选择或更换音色。
- 不增加音色购买、克隆、训练或授权管理。
- 不在本版本重构后端为新的前端 API 架构。
