## 1. 目标

把已经落地的素材底座、数字人混剪、项目剪辑、包装、质检和发布包能力，组织成普通同事第一次使用时无需培训、无需说明书、无需命令行即可完成任务的本地工作台。

本产品不是通用视频编辑器，也不是剪映替代品。它从明确的业务路线和本地素材范围开始，自动完成素材分析、分镜、粗剪、包装、精剪、质检和发布准备；使用人只在关键节点确认并纠正自动结果。

成功不以“页面能点击”或“生成了 MP4”为准，而以真实任务从本地素材进入系统、经过四道人工作业门禁、产生可追溯发布包为准。

## 2. 继承关系

本设计继承以下既有设计和计划：

- 视频生产总工作流：统一主链、门禁、数据契约和成功指标。
- 大素材渐进式资产层：本地素材登记、扫描、预览、离线与恢复。
- 项目和数字人子流程：真实性、文案、场景卡、B-roll 与画面锁定。
- 包装、字幕声音、质检和发布子流程：资产组合、候选成片、完整审片和发布包。
- P2/P3 与新疆数字人验收计划：真实渲染、依赖快照、QA 和发布门禁。

本设计新增同事使用入口、素材范围选择、任务状态、AI 操作边界、异常恢复和无培训可用性标准。早期“近期不开发独立操作界面”的阶段性边界由本次工作台决策替代；底层数据契约和质量门禁继续沿用。

## 3. 方案选择

考虑过三种方案：

1. 继续提供命令行或一次性脚本：开发量最小，但同事必须理解目录、参数和日志，不满足无需培训目标。
2. 建设完整多轨视频编辑器：自由度最高，但会重复建设剪映能力，明显扩大范围。
3. 本地混合工作台：用任务中心承接自动流程，用受约束的粗剪区完成必要纠错，用右侧对象面板替换镜头、字幕、声音和包装。

采用第三种。它借用剪映用户熟悉的预览、时间线、拆分、删除、排序和撤销心智，但不允许从空白多轨工程自由创作。

## 4. 产品边界

第一版必须支持：

- 从本机硬盘和移动硬盘选择任务素材。
- 选择业务路线并收集对应强制输入。
- 展示等待、排队、处理中、暂停、阻塞、失败和完成状态。
- 完成十二步主链及四道人工门禁。
- 在粗剪阶段拆分、删除、排序、调整片段边界、替换、撤销和重做。
- 查看 AI 推荐理由，拒绝、纠正或局部重新推荐。
- 自由组合并确认本片包装方案。
- 浏览器关闭或应用重启后恢复任务。
- 完整观看候选成片后导出发布包或可编辑素材包。

第一版不支持：

- 剪映式任意多轨创作、关键帧动画和复杂特效。
- 剪映原生工程文件承诺。
- 自动登录或发布到视频号、抖音、小红书。
- 平台派生剪辑版本。
- 多人实时协作、云素材中心和复杂版权审批。
- 默认调用视频生成模型补画面。

复杂需求通过人工接管包转入剪映，不让使用人从原始素材重新整理。

## 5. 用户与信息架构

主要用户是会使用剪映、但不应接触代码和命令行的业务同事。界面必须说明当前阶段能做什么、为什么暂停、下一步是什么，以及操作会影响哪些后续环节。技术名词默认翻译为业务动作，FFmpeg、Whisper、SQLite、模型 ID 和脚本参数只在设置或诊断详情中出现。

桌面端采用三层结构：

1. 左侧全局导航：任务、镜头素材、包装素材、设置，可隐藏。
2. 中间上下文栏：任务页显示快捷任务列表；素材页显示目录或资产分类；设置页显示设置分类。非任务模块不保留任务列表。
3. 右侧主内容区：任务中心、列表、新建任务、阶段工作区或素材管理。

主题支持明亮、暗色和跟随系统，并在本机持久化。

任务中心提供同一数据的两种视图：

- 看板用于判断下一步，至少包含等待我处理、自动处理中、排队、阻塞/失败、最近完成。
- 列表用于搜索、排序和批量查看。
- 看板不能通过任意拖拽跨越工作流门禁。

## 6. 业务路线与输入

用户首先选择三类生产路线：

1. 数字人混剪。
2. 项目宣传片。
3. 信息流广告混剪。

数字人混剪再选择城市矩阵或财税业务配置，以继承各自的事实核验、术语和画面边界。信息流广告是现有代码支线，在本设计中纳入统一入口，但不得绕过统一任务、素材、质检和交付规则。

路线强制输入：

- 数字人混剪：禅镜最终数字人 MP4、禅镜实际使用的最终口播文案、本次 B-roll 素材范围。
- 项目宣传片：项目主素材文件夹、项目真实资料、已有文案或“由系统起草待确认文案”的选择。
- 信息流广告：产品或活动主素材文件夹、广告文案或文案需求、配音方式、目标时长。

项目已有文案时优先使用并核验。没有文案时，文本模型只能根据真实资料和可用素材起草，输出必须人工确认。数字人生成完成后，剪辑阶段不得静默改写实际口播文案。

## 7. 本次素材范围

“镜头素材库”管理本机目录和素材索引；“本次素材范围”是单个任务允许使用的目录集合。

每个任务包含：

- 一个必选主素材文件夹，对应本次项目、项目、数字人或广告。
- 零到多个本次指定的通用素材文件夹。
- 用户允许后启用的系统默认通用素材文件夹。
- 独立的包装素材库，不与镜头素材混放。

镜头匹配优先级固定为：

1. 本次主素材文件夹中的真实素材。
2. 本次指定的通用素材。
3. 系统默认允许的通用素材。
4. 同一对象的真实图片、地图、参数卡或信息卡。
5. 明确确认后才可调用的视频生成模型。

其他项目专属素材不得自动进入任务。通用素材只能表达概念和气氛，不能冒充具体项目、企业、项目或事件实景。每个镜头必须显示来源类型、目录名称和必要警告。

新建任务时自动快速增量检查当前目录。镜头素材页和包装素材页均提供“检查新增与更新”。移动硬盘离线时只标记离线，不删除记录；重新连接或盘符变化后通过素材身份和指纹恢复。

任务创建时保存素材范围与指纹快照。文件新增、改名、删除或变化时，先展示影响范围，再决定局部同步，不能静默替换已确认镜头。

## 8. 统一主链与门禁

界面完整显示十二步：

创建与预检 → 文案锁定 → 素材增量同步 → AI分镜推荐 → 粗剪 → 调整画面顺序 → 画面锁定 → 包装方案确认 → 精剪成片 → 自动质检 → 完整审片 → 发布包。

四道人工门禁：

1. 文案锁定。
2. 画面和顺序锁定。
3. 包装方案确认。
4. 从头到尾完整观看并确认可发布。

未通过前一道门禁，不能进入依赖它的后续阶段。自动步骤可以连续执行，但在输入缺失、素材低置信度、真实性或隐私冲突、空间不足、付费调用、首次新音色或技术异常时暂停。

## 9. 创建与预检

新建任务依次完成路线、输入、素材范围、用途、目标时长和创建前预检。

预检必须说明：

- 强制输入是否齐全。
- 主素材和通用素材目录是否在线及是否变化。
- 当前重任务槽位和排队情况。
- 预计机器总耗时与人工操作时间。
- 预计新增磁盘空间。
- 预计 API 费用和不包含的潜在费用。
- 四次人工确认。
- 真实性、隐私、授权和必须真实呈现对象提醒。

缺失画面生成不能混入模糊总价。确认真实缺口后，才单独展示模型、数量、预计费用和替代选项。

## 10. AI 能力分工

- 通用文本模型：项目文案草稿、文案核验辅助、场景意图、包装推荐说明、发布文字。
- 素材检索与视觉理解：本地镜头标签、摘要、语义匹配和候选排序。
- faster-whisper：本地转写和词级时间戳。
- TTS：配音或补录时的试听和正式语音。
- 视频生成模型：只处理已经确认的画面缺口。
- FFmpeg 与本地规则：代理、渲染、音频处理和技术质检。

后台分析只显示状态。会生成、改写、付费或影响版本的 AI 操作必须有明确按钮，并在采用前说明用途、输入、费用、影响范围和是否覆盖。默认生成候选，不直接覆盖人工决定。

AI 推荐必须可拒绝、纠正、重新推荐，并显示理由和来源。AI 不得代替四道人工门禁。

设置页按能力配置服务。API Key 由设置页录入、遮蔽并测试连接，目标存储为 Windows 凭据管理器等本机安全存储；不得写入项目数据库、Git、任务导出物或日志。现有 .env 只作为迁移兼容入口。

## 11. 粗剪编辑边界

粗剪是系统根据场景卡、本地素材和时间码组装的 rough-v1，不是凭空生成的视频。

使用人可以选择、拆分、删除、排序、调整进入/退出边界、替换镜头、局部要求 AI 重荐、撤销、重做和恢复历史粗剪版本。

系统维护旁白、B-roll、字幕时间和包装依赖。第一版不允许自由新增多条轨道、任意叠加图层或制作复杂动画。字幕、声音和包装在画面锁定后通过对应面板配置，不在粗剪时间线自由拖动。

选中对象后，右侧显示旁白、时间范围、素材来源、真实性提示、系统建议和替换候选。替换默认只影响当前场景。

## 12. 包装素材与本片方案

包装素材库保存 AI 音色、BGM、音效、字幕模板、字体、信息卡、Logo、水印、贴纸和花字。本片包装方案是任务对这些资产的组合及版本快照。

系统推荐二至三套方案。使用人可以整套采用、替换单项、关闭非必要资产、从空白组合、保存个人方案。团队方案的发布需要权限。

确认前提供短预览。确认后才执行字幕、混音、视觉包装和精剪。资产缺失、授权不清或不可用时显示备用项，不能静默替换。

## 13. 状态、队列和后台任务

单机同一时间只运行一个识别、代理、视频生成或渲染重任务；轻量浏览和文案编辑可以继续。

任务运行状态至少包含草稿、等待我处理、排队、自动处理中、暂停、阻塞、失败、最近完成和取消。工作流阶段与运行状态分开，例如“精剪成片”可以处于排队、处理中或失败。

队列显示当前重任务、排队顺序、预计开始时间、进度和预计剩余时间，并支持安全暂停或取消。关闭浏览器不能中断后台任务；本地服务重启后从 SQLite 主账本和检查点恢复。

## 14. 版本、锁定与返工

版本沿用 rough-v1 → rough-v2 → picture-lock-v1 → candidate-v1 → candidate-v2 → final-v1。

锁定后的修改先展示影响范围。确认后创建新版本，不覆盖历史；只重跑受影响的文案、时间轴、镜头、字幕、声音、包装或 QA。

- 字幕错字只更新字幕和最终渲染。
- 单句文案变化更新该句及必要的后续时间对齐。
- 镜头替换重新检查该场景和包装兼容性。
- 画面结构变化使当前 picture lock 失效并重新确认。
- 历史候选、人工决定和发布包保持可追溯。

## 15. 质检、审片与发布

自动质检检查编码、比例、分辨率、黑帧、冻结、静音、削波、字幕、响度、重复、素材指纹、包装一致性、来源、隐私和授权。自动质检无阻断项不等于可发布。

完整审片页面记录实际播放进度。未从头到尾观看当前候选版本时，“确认可发布”不可用。问题按文案、素材、节奏、字幕、声音、包装或技术返回对应节点，并创建新候选版本。

通过后，用户可以使用系统封面候选，或导出关键帧与品牌信息交给自有封面工具。发布包至少包含最终 MP4、封面或待补封面标记、发布文字、发布检查、QA 报告和版本信息。可编辑交付额外包含基础视频、分轨音频、字幕和素材时间码。不自动上传平台。

## 16. 异常与恢复

必须覆盖目录离线、盘符变化、文件变化、空间不足、工具失败、模型超时或配额不足、包装资产缺失、浏览器关闭和服务重启。

异常页回答：发生什么、已经完成什么、尚未执行什么、是否产生费用、数据是否安全、下一步是什么。恢复后从最后一致检查点继续，不从头重扫或静默重复付费。

视频生成失败不得无限自动重试。是否重试、预计费用和是否复用已有结果由使用人确认。取消任务保留原素材和历史记录。

## 17. 技术架构

采用本地 Web 工作台加本地后台服务：

浏览器工作台 → 本地应用服务/API → SQLite 主账本与任务状态机 → 单重任务队列/工作进程 → 现有 media_catalog、TypeScript、Python、Whisper、FFmpeg → 本地输出与发布包。

浏览器只负责交互，不能拥有任务生命周期。后台负责状态机、队列、检查点、版本和恢复。现有 CLI 和渲染脚本通过适配层接入，前端不能绕过 SQLite 直接拼接渲染命令。

原片只读。模型只读取必要的结构化摘要、标签、缩略图、代理和时间码；完整大视频不上传给通用模型。JSON 是导出物，不能反向覆盖主账本。

## 18. 实施切分

1. 工作台骨架：任务中心、状态机、素材目录、设置和真实 SQLite 只读展示。
2. 数字人纵切：用已验收的 p2-xinjiang-v2 打通创建、门禁、渲染、QA 和发布包。
3. 项目纵切：使用真实项目主目录和通用素材目录，打通文案、匹配、粗剪和发布。
4. 恢复与安全：队列、关闭续跑、移动盘重连、失败恢复、密钥安全和付费确认。
5. 同事试用：修复无指导测试中的理解、误操作和恢复问题，再扩展信息流广告。

不得同时铺开全部路线。数字人稳定后再进入项目；项目完成后才把信息流广告支线纳入统一入口。

## 19. 验收标准

设计原型门禁：

- 使用人能从任务中心判断当前要做什么。
- 能区分主素材、通用素材和包装素材。
- 能看懂十二步主链、四道门禁和运行状态。
- 能理解 AI 只推荐或生成候选，不会静默覆盖。
- 能从典型异常页找到恢复入口。

真实纵切门禁：

- p2-xinjiang-v2 从真实 SQLite 和本地素材进入工作台。
- 不能绕过四道门禁。
- 关闭浏览器后任务继续，重开后状态一致。
- QA 通过且完整观看后才能生成发布包。
- 输出能追溯素材 ID、场景卡、包装方案、快照、QA 和人工决定。

无培训可用性门禁：

- 原型阶段至少 3 名目标同事无指导测试，所有人都能说明当前阶段和下一步，不出现不可恢复死路。
- 内测阶段 5 名目标同事中至少 4 名不依赖外部说明或口头培训，独立完成一条标准任务。
- 门禁绕过、跨项目素材误用、重复付费和原素材损坏必须为 0。
- 沿用原计划目标：标准任务约 30 分钟达到可发布条件；成熟后每天投入 2 小时完成 4 条标准短视频。
- 未达到的门禁如实记录，不以“基本可用”替代。

## 20. 红队场景

发布前验证连续场景：使用人锁定画面、确认包装后修改一句文案；同时移动硬盘离线，视频生成服务已计费但结果未下载，随后关闭浏览器并重启应用。

系统必须保留旧版本，明确失效门禁，不跨项目替换，不重复收费，恢复已有结果或要求人工决定，从一致检查点继续，最终发布包只绑定重新确认后的当前版本。
