# 剪辑工作台豆包音色自动发现与任务选择设计

日期：2026-09-14

> 历史说明：本文的数据模型、音色选择和任务冻结设计继续有效；凭据与首次配置说明已由 2026-09-15《剪辑工作台 UI 系统化设计》取代。新版普通流程使用豆包 API Key 合成，AppID/Access Token 只保留为旧版兼容项。下文保留原始记录用于追溯，不作为当前操作手册。

## 背景与目标

当前设置页把配音能力建模成“模型配置 + 手工音色 ID”。用户既需要填写“精确模型 ID”，又需要填写无法从界面理解的“音色 ID”；信息流广告任务只能选择整条配音配置，不能为本条视频单独选择声音。

本次调整的目标是：豆包配音账号保存成功后，由剪辑工作台使用火山引擎 Access Key ID、Secret Access Key 读取可用音色，再使用豆包 AppID、Access Token 完成实际合成；设置页用可读名称选择常用音色，信息流广告任务始终展示音色选择器，并把本条视频实际选择的音色冻结到任务中。普通用户不再输入模型 ID 或音色 ID。

本设计只取消产品内置的固定音色，不取消用户自己设置常用音色。首次配置必须由用户选择；以后新任务可以预选用户的常用音色，但选择器始终可见、可以修改。

## 方案决定

采用“配音服务配置 + 音色目录 + 任务级选择”三层结构：

1. 供应商账号保存连接和鉴权信息，包括火山 OpenAPI AK/SK、豆包 AppID/Access Token、请求地址和配音服务版本。
2. 配音配置表示一个可用的豆包配音服务，不再代表某一个固定音色；它可以保存一个由用户选择的常用音色。
3. 新建信息流广告任务时，用户在所选配音配置的兼容音色中选择本条视频的声音；任务创建后冻结精确音色 ID、服务版本和供应商快照。

不采用以下方案：

- 固定使用“阳光青年 2.0”：无法满足不同视频选择不同声音的要求。
- 为每个音色创建一条模型配置：会产生大量重复账号和配置，任务页也难以理解。
- 继续允许普通用户手填音色 ID：容易填错，也无法知道账号实际能使用哪些音色。
- 在执行任务时临时请求音色列表：外部接口波动会改变已创建任务的结果，破坏任务可复现性。

## 上游能力与边界

豆包不是使用一个通用的“模型 API Key”同时完成目录和合成。官方 `ListSpeakers` 属于 `speech_saas_prod` 控制台 OpenAPI `2025-05-20`，使用火山引擎 Access Key ID 与 Secret Access Key 签名；实际 TTS 合成继续使用豆包 AppID 与 Access Token。剪辑工作台按用户选择的配音服务版本映射 Resource ID，界面只展示“豆包语音合成 1.0”“豆包语音合成 2.0”等可读名称，不要求用户填写内部标识。

管理员是拥有火山引擎账号或 IAM 权限的人。本地版不集中托管团队密钥：每台电脑首次使用时由管理员录入一次 AK/SK、AppID 和 Access Token，之后该电脑上的普通同事只选择音色。密钥不会随 GitHub、ZIP 或 SQLite 同步到其他电脑。

本版本自动发现官方列表接口返回的音色。账号自有的复刻音色若未出现在该接口中，不在 `v0.9.0-beta.2` 新增范围内；升级前已经保存且检测可用的音色会作为“原有音色”保留，不要求重新输入，也不影响历史任务。后续可以增加独立的账号自有音色适配器，而不改变本设计的数据模型。

官方依据：

- [大模型音色列表（新接口）](https://docs.volcengine.com/docs/6561/2160690?lang=zh)
- [ListSpeakers OpenAPI `2025-05-20`](https://api.volcengine.com/api-docs/view?action=ListSpeakers&serviceCode=speech_saas_prod&version=2025-05-20)
- [豆包语音合成 API 接口文档](https://docs.volcengine.com/docs/6561/1829010?lang=zh)

## 设置页交互

### 豆包账号

豆包 TTS 供应商表单保留：

- 账号名称
- Access Key ID
- Secret Access Key
- AppID
- Access Token
- API 请求地址
- 配音服务版本

Secret Access Key 与 Access Token 以版本化双密钥包写入当前电脑的同一条 Windows 凭据记录；Access Key ID 与 AppID 作为非密钥配置写入 SQLite。服务版本使用下拉选择并由后端映射 Resource ID，不显示 Cluster、Resource ID、模型 ID 或音色 ID。历史账号中已有的 Cluster 继续兼容，旧的纯文本凭据按 Access Token 读取，但不作为普通用户的新建字段。

账号保存后提供“获取/刷新音色”操作。首次没有成功取得音色目录时，不能创建新的豆包配音配置；页面保留账号和凭据，显示可执行的错误原因与重试入口。

### 配音配置

配音卡片只列出与配音兼容的供应商账号，不再把智谱文本账号等无关账号放进下拉框。

选择豆包账号后，卡片显示：

- 服务版本与最近刷新时间
- 可搜索的音色下拉框，主标签为中文名称
- 可用元数据，包括语言、性别、风格或场景；上游缺失的字段不显示
- “试听”操作，使用短句执行真实 TTS 检测
- “设为常用音色”选项

“精确模型 ID”和“音色 ID”两个自由输入框对豆包账号完全移除。音色 ID 只作为下拉选项的内部值传给后端。

OpenAI 兼容等没有标准音色目录接口的高级供应商维持现有手工模型/音色配置，不伪造自动发现能力；这类入口与豆包的普通流程分开展示并明确标记“高级兼容”。

## 新建任务交互

信息流广告的新建表单按以下顺序工作：

1. 用户选择一个最近 24 小时内检测可用的配音配置。
2. 页面加载该配置兼容的音色目录，并始终展示“本条视频音色”选择器。
3. 如果用户设置过常用音色，页面预选它；用户可以改成任意可选音色。
4. 如果没有常用音色、常用音色已失效或目录为空，必须由用户明确选择，不能提交空值，也不能静默换成其他声音。
5. 用户可以在创建任务前试听当前选择；试听失败时保留选择并显示原因，不能把该次失败当作成功。

数字人口播路线使用原视频声音，不显示此选择器。历史信息流广告任务继续显示并使用当时冻结的音色，不受默认项或目录刷新影响。

## 数据模型与迁移

新增迁移 `030_tts_voice_catalog.sql`，建立 `tts_voice_catalog`：

- `account_id`：所属供应商账号
- `resource_id`：上游配音服务版本
- `voice_id`：执行 TTS 时使用的精确音色标识
- `display_name`：界面名称
- `language`、`gender`：可选归一化字段
- `styles_json`：可选风格列表
- `preview_url`：上游提供时保存；没有时使用剪辑工作台实时短句试听
- `source`：`provider_catalog` 或 `legacy_saved`
- `selectable`：当前是否允许新任务选择
- `metadata_json`：上游其余非敏感元数据
- `last_seen_at`、`updated_at`：刷新状态

主键为 `(account_id, resource_id, voice_id)`。表中不得保存 Access Token、请求头或任何凭据。刷新采用整批事务：成功后更新本批出现的记录，并将同账号、同服务版本中已消失的旧目录项标记为不可选；刷新失败时不清空上一次成功目录。

同一迁移建立 `tts_voice_catalog_state`，以 `(account_id, resource_id)` 为主键保存 `status`、`last_attempt_at`、`last_success_at`、`last_error_code` 和脱敏后的 `last_error_message`。即使账号从未成功返回音色或目录为空，页面也能显示准确的刷新状态。

供应商账号的 `settings_json` 新增 `tts_resource_id` 和 `access_key_id`；现有 `credential_ref` 仍是唯一的 Windows 凭据引用，它指向同时包含 Access Token 与 Secret Access Key 的版本化双密钥包。旧的非 JSON 凭据继续解释为仅包含 Access Token。豆包配音配置的 `settings_json` 保存：

- `protocol`
- `resource_id`
- `default_voice_id`

为兼容现有代码，任务冻结快照中的实际选择仍写入 `profileSettings.voice`，同时写入 `profileSettings.resource_id` 和可读的 `profileSettings.voice_name`。运行时只信任冻结的 `voice`，不重新读取当前常用音色。

迁移不批量改写旧任务。数据库启动迁移完成后运行一次幂等的旧配置导入；现有豆包配音配置如果包含 `settings.voice`：

- 把该值导入目录为 `legacy_saved`；
- 将它设为该配置的 `default_voice_id`；
- 保留原来的 `settings.voice`，直到新代码完成读写兼容；
- 若后续目录刷新找到相同 `voice_id`，用官方名称和元数据补全，来源升级为 `provider_catalog`；
- 若没有找到，但原配置最近检测可用，仍以“原有音色”显示并允许继续使用。

## 应用内部接口

新增以下本地接口：

- `GET /api/settings/provider-accounts/{accountId}/voices`：读取已缓存目录和刷新状态，不访问上游。
- `POST /api/settings/provider-accounts/{accountId}/voices/refresh`：用凭据访问上游，归一化并事务写入目录。
- `GET /api/settings/model-profiles/{profileId}/voices`：返回与该配音配置服务版本兼容的可选音色、常用音色和目录状态，供设置页与任务页共用。
- `POST /api/settings/model-profiles/{profileId}/voice-test`：使用请求体中的 `voiceId` 生成短试听；只接受该配置目录内可选的音色，历史 `legacy_saved` 音色必须已检测可用。音频写入现有预览缓存，响应返回本地试听 URL，不在 JSON 中传输音频正文。

创建豆包配音配置时，前端提交 `resourceId` 和 `defaultVoiceId`，不提交自由文本 `model` 或 `voice`。后端从供应商预设和服务版本生成兼容的内部模型标识，拒绝账号不匹配、服务版本不匹配或目录中不存在的音色。

信息流广告的预检与创建请求新增 `tts_voice_id`。后端同时校验 `tts_profile_id` 和 `tts_voice_id`，然后复制所选配音配置快照、覆盖快照中的 `profileSettings.voice`，重新计算快照摘要并写入 `task_model_bindings`。前端值不能直接越过目录校验进入运行时。

所有接口错误继续返回安全错误码和中文修复建议；响应与日志不包含 Access Token。

## 运行时与确定性

`v0.9.0-beta.2` 不为发现音色而切换现有已验收的合成协议。音色目录适配器和 TTS 合成适配器分开：前者负责官方列表，后者继续使用配音配置经过真实试听验证的请求协议。目录返回的音色默认可选；用户对某个音色执行试听失败后，该音色在问题修复或目录刷新前标记为不可选，但不会把同一配音配置下的其他音色一并判为不可用。

任务执行读取冻结快照中的账号、请求地址、协议、服务版本和音色 ID。目录刷新、修改常用音色、删除目录缓存或供应商以后调整音色名称，都不能改变已创建任务。指定音色调用失败时任务明确失败，不自动换成别的声音。

## 缓存、失败与降级

- 尚未配置账号：任务页提示前往设置，不显示无意义输入框。
- 鉴权失败：标记刷新失败，保留旧缓存，提示检查 Access Key ID、Secret Access Key、IAM 权限与服务开通状态。
- 服务版本未开通：提示当前账号无该服务权限，不回退到另一版本。
- 网络或上游超时：保留旧缓存并标记“目录可能已过期”，允许用户重试；已经检测可用的缓存音色仍可选择。
- 目录成功但为空：显示“当前账号与服务版本没有返回可用音色”，不允许创建新的豆包配音配置。
- 音色从新目录消失：不再供新任务选择；历史任务及已冻结任务仍保留精确 ID。
- 配音配置检测失败：该配置不能进入新任务选择器。
- 单个音色试听失败：只标记并提示该音色，不静默替换，也不影响同配置下其他音色。

## 安全要求

- Secret Access Key 与 Access Token 只存当前电脑的 Windows 凭据管理器，不能进入 SQLite、任务快照、接口响应、浏览器状态、GitHub、ZIP 或日志。
- Access Key ID 与 AppID 属于非密钥标识，可以进入账号配置；页面不能回显任何已保存密钥。
- AppID、Resource ID、音色 ID 属于非密钥配置，可以进入快照；页面默认只显示可读名称。
- 上游错误在返回页面前必须脱敏，不能回显 Authorization、Access Token 或完整请求头。
- 音色目录缓存只保存官方返回的非敏感描述数据。

## 测试与验收

自动化测试至少覆盖：

1. 豆包目录适配器使用正确的 Access Key ID、Secret Access Key 与 Resource ID 签名请求，请求日志会脱敏。
2. 上游多种音色响应能归一化为稳定目录；刷新成功会停用消失项，刷新失败不会清空旧缓存。
3. 旧 `settings.voice` 自动导入 `legacy_saved`，旧任务快照和摘要仍可读取、执行。
4. 豆包配音卡不显示“精确模型 ID”和“音色 ID”，也不会列出不兼容的文本账号。
5. 用户能刷新音色、按中文名称选择、试听并设置常用音色。
6. 新建信息流广告始终展示音色选择器；未选择不能提交，修改后冻结的是本条视频选择而不是当前常用值。
7. 刷新目录或修改常用音色后，已有任务的 `profileSettings.voice` 与摘要不变。
8. 伪造其他账号、其他服务版本或不可选的 `tts_voice_id` 会被后端拒绝。
9. 指定音色运行失败会明确报错，不会自动换音色。
10. 真实豆包账号至少完成一次“刷新目录 → 选择两个不同音色分别试听 → 建立任务 → 核对冻结音色”的人工验收。

## 发布与同事升级

实现和全部门禁通过后发布新版本 `v0.9.0-beta.2`，新建 Git 标签和 GitHub Release，不覆盖 `v0.9.0-beta.1`。发布包需包含迁移 `030_tts_voice_catalog.sql`、更新后的用户指南和升级说明。

同事应把新 ZIP 解压到新目录，并按升级说明备份、复制原有 `runtime/workbench/catalog.sqlite` 后启动；首次启动自动执行数据库迁移。由于 Windows 凭据不随安装包和数据库迁移，每台新电脑首次使用时仍需由管理员录入四项凭据一次。升级完成后原有豆包配置显示为“原有音色”或匹配到的官方中文名，不要求再次填写 ID。发布验收必须用数据库副本演练一次升级，不能直接拿唯一的生产账本试迁移。

## 非目标

- 不在本版本管理音色克隆、训练、购买或授权流程。
- 不承诺所有第三方 OpenAI 兼容 TTS 都能自动列出音色。
- 不把音色目录刷新放进任务执行关键路径。
- 不自动替用户选择产品内置固定音色，也不在调用失败时静默降级。
- 不删除现有配音配置、历史任务或旧协议兼容代码。
