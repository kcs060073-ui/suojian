# CUTROOM 包装确认真实预览与方案闭环设计

状态：待 Peter 书面复核

日期：2026-09-20

依据：[同事视频工作台设计](./2026-09-05-colleague-video-workbench-design.md)

上游边界：[粗剪真实素材预览与编辑闭环设计](./2026-09-20-rough-cut-real-media-design.md)

## 1. 目标

恢复最初产品设计中的包装确认能力：用户在确认包装方案前，必须看到由当前画面锁、当前文案与当前包装素材真实合成的短视频，能够试听和查看具体素材，并能整套采用、复制后替换单项、禁用可选项、从空白开始以及保存个人模板。

本设计修正当前正式页面把“槽位名 + 素材 ID 列表”称为“应用前预览”的偏差。素材名称、目录状态和静态清单只能辅助选择，不能替代真实合成结果。

## 2. 成功标准

1. 选中包装方案后，页面可生成并播放 8—12 秒真实合成预览；预览使用当前已锁定画面和方案中实际选择的字幕、BGM、音效、文字卡、贴纸、花字与品牌资产。
2. 预览由正式渲染所使用的同一套包装解析和合成规则生成，不用另造一套只在页面中模拟的 CSS 动画或假音频。
3. 预览与 `picture-lock digest + packaging plan digest + renderer version` 绑定。画面锁或包装方案变化后，旧预览立即标记过期，不能继续用于确认。
4. 用户完整播放或播放到规定阈值后，才能确认该方案；服务端再次核验预览、方案和画面锁摘要一致。
5. 用户可复制推荐方案后替换单项，可关闭除字幕外的可选槽位，并可从空白方案开始组合。
6. 用户可把一个完整且有效的任务方案保存为不可变个人模板，也可把个人模板克隆到当前任务后再编辑。
7. 包装素材页提供“检查新增与更新”，能识别核心、团队扩展和个人目录中的新增、更新、缺失与无效文件；未知或授权不明文件不会自动进入正式推荐。
8. 缺文件、授权不允许、无法解码、预览生成失败或缓存过期时，页面明确指出具体槽位和素材，禁止确认，不以占位视频伪装成功。

## 3. 范围与非目标

### 3.1 本批范围

- 包装方案真实短预览及其观看确认门禁。
- 包装方案整套采用、克隆、单项替换、可选项禁用、空白组合。
- 个人模板保存、浏览和克隆使用。
- 包装资产逐项试听/查看，以及核心、扩展、个人目录的新增与更新检查。
- 数字人混剪和信息流广告两条当前可用路线；领域模型保持园区路线兼容，但园区路线的完整验收归后续批次。

### 3.2 非目标

- 不修改粗剪播放器、时间线、画面编辑或画面锁实现。
- 不建设自由多轨包装编辑器；包装仍按固定槽位组合。
- 不在本批实现完整的本地资产元数据编辑、团队晋升审批或扩展包下载器。
- 不允许扫描动作自动修改 Git 中的核心 manifest，也不自动把授权不明文件加入推荐。
- 不把短预览当成最终成片或正式 QA；预览只服务于包装方案确认。
- 不在预览时隐式发起付费 TTS。音色使用已生成的任务音频或已有试听缓存；缺少试听时明确阻断并引导先完成音色测试。

## 4. 方案选择

采用“服务端真实合成预览 + 摘要绑定缓存 + 明确观看门禁”。

- 不采用浏览器 CSS 叠层模拟，因为它无法证明 FFmpeg 最终渲染中的字体、字幕安全区、混音、动画和透明素材一致。
- 不采用每次进入页面都渲染完整成片，因为等待时间和资源消耗不适合方案比较。
- 不采用只试听单个素材后直接确认，因为用户无法判断多种包装同时出现时的密度、遮挡和声音层级。
- 生成一段低分辨率、短时长、可重复利用的合成预览；任何有效输入变化都通过摘要自然失效缓存。

## 5. 用户流程

```text
进入包装方案确认
→ 查看 2—3 套推荐、个人模板和自选组合
→ 选中一套方案
→ 逐项试听/查看素材，必要时复制为自选组合
→ 替换单项、禁用可选项或从空白开始
→ 生成真实短预览
→ 播放预览并检查字幕、声音、卡片、贴纸、花字和品牌效果
→ 不满意：继续调整，旧预览自动过期
→ 满意：确认当前预览对应的包装方案
→ 可选：把当前方案保存为个人模板
→ 进入正式渲染
```

推荐方案和个人模板本身保持不可变。用户若要修改，必须先克隆为当前任务的 draft。推荐方案可以直接预览并确认；个人模板必须先克隆，避免模板与任务状态混淆。

## 6. 真实短预览

### 6.1 预览内容

预览默认生成 8—12 秒、540×960、H.264/AAC 的低成本 MP4。它使用当前 picture lock 中的真实镜头，不使用演示色块或与任务无关的样片。

预览编排采用确定性片段：

1. 开场段展示实际锁定画面、标题卡、品牌水印和 BGM。
2. 正文段展示真实任务字幕、贴纸、花字和一次音效触发。
3. 若任务足够长，结尾段补充 CTA 或品牌元素；任务较短时按实际时长缩短，不循环伪造内容。

被选中的槽位必须在预览中出现或被明确标记为“不适用于当前任务”。页面同时展示预览覆盖清单，不能把未实际渲染的槽位显示为已验证。

短预览用于判断视觉与声音组合，不承诺等同最终节奏。播放器旁固定显示“包装预览片段，不是最终成片”。

### 6.2 与正式渲染的一致性

预览层只负责：

- 选择确定性的短时间范围。
- 降低分辨率和码率。
- 把当前 draft 方案作为显式输入。

资产解析、字幕样式、声音层级、卡片/贴纸/花字布局和品牌叠加必须复用正式渲染适配器的公共构建函数。不能在 `packaging_preview.py` 中复制一套不同参数。

预览不得写入 packaging confirmation gate，不得创建正式 render snapshot、QA 报告或审片候选，也不得改变后续阶段状态。

### 6.3 摘要与缓存

每个预览记录以下不可变输入：

```json
{
  "taskId": "task-...",
  "planId": "pp-...",
  "pictureLockDigest": "...",
  "planDigest": "...",
  "rendererVersion": "...",
  "previewProfile": "portrait-540p-v1"
}
```

摘要完全相同且文件仍存在时复用已有预览；任一字段变化时生成新预览，旧记录保留为 stale 证据，但页面不再允许用它确认。

预览文件写入工作台缓存目录 `cache/packaging-previews/<task-id>/`，数据库只保存相对路径、大小、时长、摘要和状态，不保存浏览器可见的绝对路径。清理缓存后记录变为 missing，可重新生成。

### 6.4 观看门禁

播放器播放到预览时长的 90%，或触发正常 `ended`，前端提交观看完成。服务端记录 `viewed_at` 和对应摘要。

确认包装方案时必须提交 `previewId`。服务端在同一事务前重新验证：

- 预览状态为 ready，文件存在且可解码。
- `task_id`、`plan_id` 与请求一致。
- 当前 picture-lock digest 与预览一致。
- 当前 plan digest 与预览一致。
- 预览已完成观看。

任何条件不满足都返回稳定错误并要求重新预览，不允许仅由前端按钮状态承担门禁。

## 7. 数据模型

新增迁移 `033_packaging_preview_and_catalog_check.sql`。

### 7.1 `packaging_preview_artifacts`

关键字段：

- `preview_id`：主键。
- `task_id`、`plan_id`：所属任务和方案。
- `picture_lock_digest`、`plan_digest`、`renderer_version`、`preview_profile`。
- `status`：`queued / rendering / ready / failed / stale / missing`。
- `rel_path`、`duration_seconds`、`size_bytes`。
- `coverage_json`：实际预览到的槽位及未覆盖原因。
- `error_code`、`error_detail`。
- `viewed_at`、`created_at`、`updated_at`。

任务或方案删除时级联删除数据库记录；物理缓存仍由受控缓存清理器回收。已确认方案对应的预览记录保留，用于解释当时确认了什么。

### 7.2 `packaging_catalog_checks`

保存每次检查的范围、目录摘要、开始/结束时间和统计：`added / updated / missing / invalid / unchanged`。具体差异保存在 JSON 结果中，只记录相对目录、资产 ID、状态和原因，不向浏览器返回任意绝对源路径。

当前 `packaging_templates` 保持不可变快照模型；本批补充公开的列表和保存入口，不修改其既有数据语义。

## 8. 领域模块

### 8.1 `media_catalog/packaging_preview.py`

职责：

- 根据任务、画面锁和方案生成 canonical preview input。
- 校验每个方案槽位的文件、授权、适用路线与可解码性。
- 计算摘要并查询可复用缓存。
- 创建预览记录和 worker job。
- 调用公共渲染构建函数生成短预览。
- 记录覆盖清单、失败原因、观看完成和 stale 状态。
- 在确认方案前执行服务端一致性校验。

该模块不处理 HTTP，不接受任意本机路径，也不直接确认包装 gate。

### 8.2 `media_catalog/packaging_catalog_check.py`

职责：

- 只扫描配置允许的核心、团队扩展和个人包装目录。
- 对 manifest 已登记文件比较大小、mtime、快速指纹和可解码状态。
- 发现未登记的新文件、内容更新、登记但缺失的文件和格式异常文件。
- 对未知或授权不明文件只生成待处理项，不自动写入核心 manifest，不使其可选。
- 输出稳定差异结果，供包装素材页显示。

### 8.3 `media_catalog/packaging_plan.py`

复用已有 `disable_optional_slot()` 与 `save_personal_template()`；补充个人模板列表和确认预览校验接口。字幕仍是必选槽位，其余槽位允许关闭。已确认方案继续保持不可变，修改必须克隆为新 draft。

## 9. 工作台接口

### 9.1 方案与模板

```text
POST /api/tasks/{task_id}/packaging/compose
POST /api/tasks/{task_id}/packaging/{plan_id}/save-template
GET  /api/packaging-templates?route={route}
```

`compose` 延续现有协议：`enabled: false` 关闭可选槽位；前端不再隐藏这一能力。保存模板只接受当前任务拥有的完整方案和非空模板名。模板列表只返回与任务路线兼容的不可变快照。

### 9.2 真实预览

```text
POST     /api/tasks/{task_id}/packaging/{plan_id}/preview
GET      /api/tasks/{task_id}/packaging/{plan_id}/preview
POST     /api/tasks/{task_id}/packaging-previews/{preview_id}/viewed
GET|HEAD /api/tasks/{task_id}/packaging-previews/{preview_id}/media
POST     /api/tasks/{task_id}/packaging/{plan_id}/confirm
```

- `POST .../preview` 命中有效缓存时直接返回 ready；否则返回 `202` 和现有 job 投影。
- `GET .../preview` 返回当前摘要对应的最新状态，不返回过期预览作为当前结果。
- media 接口复用工作台认证、HTTP Range、`no-store`、`nosniff` 和客户端断开处理。
- `confirm` 请求体必须包含 `previewId`；老的无预览确认调用返回 `PACKAGING_PREVIEW_REQUIRED`。

稳定错误至少包括：

- `PACKAGING_PREVIEW_REQUIRED`
- `PACKAGING_PREVIEW_STALE`
- `PACKAGING_PREVIEW_NOT_VIEWED`
- `PACKAGING_PREVIEW_MEDIA_MISSING`
- `PACKAGING_PREVIEW_RENDER_FAILED`
- `PACKAGING_ASSET_UNAVAILABLE`
- `PACKAGING_ASSET_LICENSE_BLOCKED`

### 9.3 素材检查

```text
POST /api/packaging-catalog/check
GET  /api/packaging-catalog/checks/latest
```

检查通过现有持久任务队列执行。页面显示队列状态和最近结果，不因关闭浏览器丢失。重复点击时复用或拒绝同范围的活动任务，避免并发扫描同一目录。

## 10. 工作台界面

### 10.1 包装方案页

主区域保留“系统推荐 / 我的模板 / 我的自选组合”三组方案卡。右侧检查器调整为：

1. 顶部真实视频播放器和预览状态。
2. “生成预览 / 重新生成预览”按钮。
3. 实际覆盖槽位清单及未覆盖原因。
4. 方案槽位列表，每项显示名称、来源层、授权、可用状态和单项试听/查看入口。
5. draft 编辑区：替换单项、关闭可选项、从素材目录选择。
6. “保存为个人模板”和“确认这个包装方案”。

确认按钮只有在当前摘要的预览 ready 且已观看时启用；服务端仍执行最终校验。预览渲染中、失败或过期都有明确状态，不沿用旧视频假装当前方案已预览。

槽位名称使用中文，不向普通同事直接暴露 `subtitle / bgm / sfx` 等内部键。编辑列表必须补上当前遗漏的音效槽位。

### 10.2 单项预览

- BGM、音效、音色：原生音频控件。
- 图片、Logo、水印：缩略图和大图查看。
- GIF/WebP/MP4 动画资产：原生动画或视频预览。
- 纯参数型字幕、文字卡和花字模板：使用统一测试文案的仓库预渲染样例；缺少样例时标记“需通过合成预览查看”，不能显示为空白成功。

单项预览只辅助选择；真实合成预览仍是确认前必经步骤。

### 10.3 包装素材页

在现有目录卡片之外显示逐项资产卡片，可按分类和来源层过滤。顶部提供“检查新增与更新”，结果分为：

- 新发现
- 内容已更新
- 登记但缺失
- 格式或解码无效
- 无变化

待处理文件显示其所属受控目录和相对路径、原因及下一步说明。未登记或授权不明的文件不能直接出现在任务可选列表。

## 11. 与粗剪分支的集成边界

本批不读取粗剪前端内部状态，也不调用粗剪浏览器播放器。唯一上游契约是持久化后的 picture lock：

- `task_id`
- 场景卡顺序和来源窗口
- picture-lock canonical digest
- 可供渲染适配器解析的锁定素材引用

如果粗剪分支最终调整字段名，由一个后端适配函数转换为包装预览输入，不让两个前端模块互相依赖。

为降低并行冲突，优先新增独立文件：

- `media_catalog/packaging_preview.py`
- `media_catalog/packaging_catalog_check.py`
- `web-ui/public/packaging-preview.mjs`
- `web-ui/public/packaging-catalog.mjs`
- 对应独立测试文件

`workbench/api.py`、`workbench/routes.py`、`web-ui/public/app.mjs` 和 `styles.css` 的接线改动在粗剪分支落定后合并，或保持为小范围、可独立挑选的提交。

## 12. 安全与失败处理

- 浏览器请求不接受文件路径；所有媒体通过任务、方案、预览或资产 ID 解析。
- 只允许受控包装目录和工作台缓存目录，拒绝 `..`、符号链接逃逸和未知 MIME。
- 源资产只读；预览只写可重建缓存。
- 预览失败不得修改方案、确认 gate 或后续阶段状态。
- 授权为 `prohibited` 或明确不允许商用时阻断；`unknown` 只能用于素材检查，不能进入正式方案。
- 预览记录中的错误详情对页面做去路径化处理；完整本机路径只留在本地诊断日志。
- 并发请求使用同一摘要的唯一约束或幂等键，避免重复渲染。
- 清理缓存不得删除源资产、manifest、个人模板或已确认方案证据。

## 13. 测试与验收

### 13.1 自动测试

按 TDD 顺序覆盖：

1. 预览输入摘要随画面锁、方案或渲染版本变化而变化，相同输入稳定命中缓存。
2. 预览只接受当前任务拥有的 draft/recommended 方案，任务外方案拒绝且不泄露路径。
3. 预览 worker 使用真实锁定媒体和实际包装资产，生成可解码的 H.264/AAC MP4。
4. 每个已选择槽位要么出现在 `coverage_json`，要么带明确不适用/失败原因；不能静默跳过。
5. 方案修改、重新锁画面和缓存删除分别产生 stale/missing 状态。
6. 未观看、过期、失败或文件缺失的预览都不能确认；ready 且已观看且摘要一致时可以确认。
7. 单项替换只改一个槽位；关闭可选槽位成功；字幕槽位不能关闭。
8. 保存个人模板生成任务无关的不可变快照；模板克隆后才可编辑。
9. 素材检查能识别新增、更新、缺失和无效文件，不修改核心 manifest，也不让未知授权素材可选。
10. media 接口覆盖认证、HEAD、Range、MIME、越权和路径逃逸。
11. UI 测试覆盖真实播放器、预览状态、音效槽位、关闭按钮、保存模板、素材检查及确认按钮门禁。
12. 现有包装确认、渲染适配、来源追溯和后续失效测试保持通过。

### 13.2 真实任务验收

使用一条已经完成 picture lock 的真实数字人任务：

1. 生成三套推荐方案并分别生成预览，三条视频能真实听见或看见对应差异。
2. 复制一套推荐，替换 BGM、禁用贴纸或音效，再生成预览；旧预览立即过期，新预览反映变化。
3. 预览未看完时不能确认；看完后可以确认，刷新页面仍保留确认和观看证据。
4. 把方案保存为个人模板，在另一条同路线任务中克隆使用，模板本体保持不变。
5. 在个人目录放入一个新文件、修改一个已有文件、移走一个已登记文件，检查结果分别识别三种变化。
6. 模拟包装文件离线或损坏，预览失败并指出具体槽位，不能确认。
7. 确认后执行正式渲染，抽查预览中出现的字幕、BGM、品牌和视觉包装与正式成片使用同一资产和参数。

信息流广告路线再执行一次最小验收：至少生成一条真实包装预览、完成观看门禁并进入正式渲染。园区路线在园区完整工作流批次统一验收。

## 14. 交付门禁

在以下条件全部满足前，不得把包装页描述为“应用前预览”或“包装确认闭环”：

- 自动测试通过。
- 真实任务预览可以播放并覆盖实际选择的包装槽位。
- 修改方案后旧预览确实失效。
- 未观看预览无法确认。
- 确认后的正式渲染与预览使用同一资产解析和包装参数。
- 新增与更新检查不会自动启用未知或无授权素材。
