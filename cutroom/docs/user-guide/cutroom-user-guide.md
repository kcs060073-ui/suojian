# CUTROOM 同事操作手册

版本：v0.9.0-beta.8（2026-09-23）
维护修订：2026-09-23（信息流真实首片闭环与发布门禁修复）
适用入口：<http://127.0.0.1:8765/>  
适用对象：没有剪辑和开发经验的普通业务同事

首次真实任务必须由普通同事本人执行，并使用[普通同事首条真实任务验收单](../validation/cutroom-colleague-first-real-task-acceptance.md)逐项记录；自动测试和维护人员代操作不能代替人工签收。

## 1. 当前能做什么

| 视频路线 | 当前状态 | 使用边界 |
| --- | --- | --- |
| 数字人混剪 | 已开放 | 底层数字人路线已有真实样片闭环；新版 CUTROOM 仍需完成一次从创建到新发布包的实操复验 |
| 信息流广告混剪 | 已开放，维护端首片已闭环 | 必须配置文案策划与配音模型，并保证每句有真实素材；仍待普通同事现场验收 |
| 园区宣传片 | 后续开放 | 当前不要创建或承诺该路线 |

CUTROOM 不是通用多轨剪辑软件。它负责把素材、文案、模型调用、画面确认、包装、渲染、质检、审片和发布包串成一条可恢复的工作流。

## 2. 安装与每天打开

### 2.1 首次安装

1. 打开 [CUTROOM v0.9.0-beta.8 下载页](https://github.com/qnwhageqlavs-jpg/cutroom/releases/tag/v0.9.0-beta.8)，下载 `CUTROOM-v0.9.0-beta.8-windows-x64.zip`，完整解压到本机可写的短路径，例如 `D:\CUTROOM-v0.9.0-beta.8`；不要在压缩包预览窗口内运行，也不要放进层级很深的目录，避免触发 Windows 路径长度限制。
2. 保持电脑联网，双击 `安装CUTROOM.bat`。首次安装文件较多，看到“安装完成”前不要关闭窗口。
3. 安装器会检查 Python 3.11、Node.js LTS、FFmpeg；缺少时通过 winget 安装，然后建立 CUTROOM 专用环境。
4. 看到“安装完成”后关闭安装窗口。

Beta 仅支持 64 位 Windows，首次安装需要网络和 winget。若公司安全策略阻止安装，请保留错误窗口并交给维护人员，不要自行下载不明运行库。

### 2.2 每天打开

固定网址：

```text
http://127.0.0.1:8765/
```

双击解压目录内的 `启动CUTROOM.bat`，等待浏览器打开固定网址。页面打不开时：

1. 确认没有移动或删除整个解压目录中的文件。
2. 再次双击 `启动CUTROOM.bat`。
3. 重新打开固定网址。

关闭浏览器不会取消后台任务。再次打开时，任务状态从本机 SQLite 账本恢复。

## 3. 首次使用顺序

1. 在“设置 → AI 服务连接”添加供应商账号。
2. 建立并测试三类模型配置。
3. 在“镜头素材”登记主素材和通用补充素材目录。
4. 在“包装素材”了解现有字幕、声音和视觉资产。
5. 回到“任务”新建视频。
6. 只按页面显示的当前动作推进。十二步阶段条中的绿色已完成步骤可以点击回看；橙色步骤始终是任务真实所在阶段，尚未开始的步骤不可点击。

回看历史步骤时，页面会显示“只读回看”和“返回当前步骤”。回看只展示当前任务保留的结果，不改变门禁、版本或后台状态；需要修改已锁定内容时，使用页面提供的“修改已锁定画面”“记录画面返工”等入口。

修改镜头或包装并重新确认后，系统生成新候选，保留旧片；新候选需要重新质检和完整审片。重复提交同一版会复用仍有效的结果。

### 3.1 选择规划方式

- 独立模式：CUTROOM 自己调用已配置的文案/分镜模型。
- Agent 模式：当前 Codex、WorkBuddy 或豆包工作模型完成文案与分镜；CUTROOM 不调用文本模型。
- 两种模式：豆包 TTS、Seedance 等生产服务仍使用 CUTROOM 各自凭据。

Agent 模式只替换文案与分镜的模型来源，不改变现有任务账本、渲染、模型配置和四个人工门禁。任务进入“AI 分镜”后，页面会显示“等待 Agent 提交规划”，请回到当前使用的 Agent 客户端继续。Agent 返回的任务地址形如 `http://127.0.0.1:8765/#/tasks/<task-id>`，需要已有工作台会话；不要在任务地址中加入启动密钥。

MCP 关闭或卸载后，CUTROOM 独立模式仍正常工作。Codex 与 WorkBuddy 的卸载脚本只移除对应客户端中的 `cutroom` 服务项，现有 CUTROOM 和任务继续可用；豆包工作通过公开的自定义连接器入口启用或移除，并连接只监听本机 `127.0.0.1` 的 HTTP MCP。维护人员按 [Agent MCP 客户端操作手册](../operations/cutroom-agent-mcp-clients.md)配置，普通同事不需要编辑客户端配置文件。

### 3.2 三种 Agent 的连接方式

| Agent | 连接方式 | 普通同事需要做什么 |
| --- | --- | --- |
| Codex | 本地 `stdio` | 安装后重新加载 MCP；不填写 URL 或请求头 |
| WorkBuddy | 本地 `stdio` | 安装后到连接器管理页信任并启用 `cutroom`，再重启 WorkBuddy 或新建会话 |
| 豆包工作 | 本机 HTTP | 启动豆包 MCP 服务，在自定义连接器中填写 URL 和 Authorization，并保持服务窗口开启 |

WorkBuddy 不需要运行豆包启动脚本，也不需要填写 Authorization。豆包工作的 HTTP 服务只监听当前电脑的 `127.0.0.1:8766`，其他电脑不能访问。

### 3.3 WorkBuddy 首次连接

维护人员在 CUTROOM 目录完成一次安装：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-workbuddy-mcp.ps1
```

普通同事随后操作：

1. 打开 WorkBuddy 的连接器或 MCP 管理页面。
2. 找到 `cutroom`，点击“信任”并确认已启用。只有写入配置还不等于当前会话已经加载工具。
3. 完全退出并重新打开 WorkBuddy，或在重新加载连接器后新建会话。
4. 发送只读验证指令：

```text
请直接调用 cutroom_get_system_status，不要创建任务，也不要改用读取配置文件或直接运行 Python 的替代方式。请分别报告 clientId、mcpToolCount 和 allowedTaskActionCount。
```

正确结果为 `clientId = workbuddy`、`mcpToolCount = 12`、`allowedTaskActionCount = 4`。

### 3.4 豆包工作首次连接

1. 按 `Win + R`，输入 `powershell` 并回车。
2. 进入实际 CUTROOM 目录；源码工作区示例为：

```powershell
Set-Location 'E:\我的AI项目\CUTROOM'
```

使用安装 ZIP 的同事应改成自己的解压目录，不要照抄示例盘符。

3. 启动豆包 MCP，并保持这个窗口开启：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-doubao-work-mcp.ps1
```

4. 再打开一个 PowerShell 窗口，进入同一个 CUTROOM 目录并显示连接字段：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\show-doubao-work-mcp-config.ps1
```

5. 打开豆包工作“插件 · 技能 · 伙伴 → 新建自定义连接器”，按下表填写：

| 字段 | 填写内容 |
| --- | --- |
| 服务器名称 | `cutroom` |
| 传输类型 | `HTTP` |
| 服务器 URL | `http://127.0.0.1:8766/mcp` |
| Header 名称 | `Authorization` |
| Header 值 | 脚本显示的完整 `Bearer <本机随机令牌>`；保留 `Bearer` 后的空格，不复制引号 |

6. 保存后发送与 WorkBuddy 相同的只读验证指令。正确结果为 `clientId = doubao_work`、`mcpToolCount = 12`、`allowedTaskActionCount = 4`。

Authorization 相当于本机连接密码，不得截图、分享、写入文档或提交 Git。若已经泄露，关闭豆包 MCP 服务，删除 `runtime\mcp\doubao-work.token`，重新启动服务并把新值更新到连接器。

### 3.5 “12 个工具”和“4 个动作”不是一回事

| 状态字段 | 正确数量 | 含义 |
| --- | ---: | --- |
| `mcpToolCount` / `mcpTools` | 12 | 查询状态、列任务、创建任务、提交规划、启动动作、查询与恢复作业等完整 MCP 工具面 |
| `allowedTaskActionCount` / `allowedTaskActions` | 4 | `cutroom_start_task_action` 这个工具允许启动的四种任务动作 |

旧字段 `agentActions` 为兼容保留，也表示四种允许动作，不代表 MCP 工具总数。四个人工门禁仍必须回到 CUTROOM 页面确认，12 个工具也不能代替人工放行。

## 4. 怎样配置大模型

### 4.1 先添加供应商账号

打开“设置 → AI 服务连接 → 供应商账号”，按页面填写：

豆包 API Key用于合成、试听和连接检测，AK/SK用于自动刷新音色目录，AppID + Access Token是旧版兼容项，可以留空。保存并检测会生成极短的测试语音。

| 字段 | 怎样填 |
| --- | --- |
| 供应商预设 | 选择接口类型，例如 OpenAI 兼容、火山方舟文本、火山方舟视频生成、豆包 TTS |
| 供应商名称 | 自己容易识别的名称，例如“智谱正式账号”“豆包配音账号” |
| 备注 | 可留空 |
| API Key / Access Token | 普通文本、视频服务使用供应商控制台生成的真实凭据 |
| API 请求地址 | 使用预设自动地址，或填写供应商给出的兼容地址 |
| 默认模型 | 可留空；填写后建立模型配置时自动带出 |
| 豆包 API Key | 新版豆包 TTS 必填，从豆包控制台“API Key 管理”中取得，用于合成、试听和连接检测 |
| Access Key ID / Secret Access Key | 自动刷新豆包官方音色目录时必填，由火山主账号或 IAM 管理员创建 |
| 豆包 AppID / Access Token | 仅旧版 V1 账号兼容使用；新版账号可以留空 |
| 配音服务版本 | 豆包 TTS 必选，按账号已开通情况选择 1.0 或 2.0 |

Secret Access Key、API Key 和 Access Token 只保存到当前电脑、当前 Windows 用户的凭据管理器，不写入页面响应、SQLite、任务快照和本手册。
普通同事只在 CUTROOM 页面中配置模型，不需要也不应编辑 `.env`。

豆包账号保存后，会按“保存凭据 → 检测连接 → 刷新音色目录”显示进度。“管理员”就是拥有火山账号或 IAM 权限、可以管理豆包 API Key 与 AK/SK 的人；如果你负责这个账号，就是你。每台新电脑都要重新录入新版 API Key 与 AK/SK，GitHub、安装 ZIP 和复制的 SQLite 都不会携带密钥。该电脑配置完成后，普通同事只需要选择中文音色名称，不再接触内部 ID。

### 4.2 再建立三类模型配置

#### 文案策划

统一用于：

- 分析或改写文案；
- 生成分镜、搜索词和 B-roll 提示词；
- 推荐重点词、标题、金句和包装方案。

数字人和信息流广告在独立模式下都需要文案策划模型；Agent 模式不使用 CUTROOM 的文本模型。

#### B-roll

仅在本地素材确实缺画面时生成视频。它是可选付费能力；本地素材匹配不需要模型。

#### 配音

用于信息流广告的音色试听和正式 TTS。数字人口播已经包含声音，不调用配音模型。

### 4.3 模型配置与豆包常用音色

- 配置名称只给人看，例如“智谱-文案策划”“豆包配音服务”。
- 文案策划和 B-roll 的模型 ID 是供应商实际开通的精确模型或推理接入点 ID。
- 豆包配音不填写模型 ID 或音色 ID：先选择配音服务版本，再从官方目录返回的中文名称中选择常用音色。
- 常用音色只是以后新广告的预选项；新建广告时“本条视频音色”始终显示，可以换成其他可用声音。
- 数字人混剪使用 MP4 自带声音，不显示配音服务和音色选择。

同一类可以保存多个模型。测试通过后可以把常用项设为默认，但新建任务时仍可选择其他可用配置。

### 4.4 测试与任务绑定

添加配置后必须点击“测试连接”：

- 文案策划发送一次极小真实请求；
- 配音生成极短测试音频；
- B-roll 测试只检查目录或模型能力，不自动生成付费视频。

只有最近 24 小时内测试成功的配置可以被新任务选择。任务创建后会冻结本次选择的供应商、请求地址、服务版本、精确音色和协议；以后修改常用项或刷新目录不会改变旧任务，调用失败也不会静默换声音。

重新测试失败后，以最新检测结果为准，不能继续使用旧的“可用”标记创建任务。排除问题后重新测试即可。

豆包常见问题：

- 显示“缺少 AK / SK”：由管理员打开该账号的“补充/更新凭据”补齐 Access Key ID 和 Secret Access Key。
- `ListSpeakers` 提示无权限：确认 AK 未禁用，并由火山主账号/IAM 管理员给该身份开通音色目录接口权限。
- 提示缺少服务版本：重新选择账号已开通的豆包语音合成 1.0 或 2.0 并保存。
- 音色目录为空：核对账号开通范围和服务版本；系统不会静默塞入默认声音。
- 试听失败：优先检查豆包 API Key、服务版本和音色授权，只有旧版账号才检查 AppID/Access Token。供应商明确提示音色不存在或不支持时，该音色暂停用于新任务；鉴权或网络故障不会被误判成音色失效。

更详细的供应商说明见 [多模型与供应商配置](../operations/model-profiles-new-api.md)。

## 5. 镜头素材怎样管理

镜头素材是视频画面，分为两种：

| 类型 | 用途 |
| --- | --- |
| 本次主素材 | 当前园区、项目、产品或广告专属画面，任务优先使用 |
| 通用补充素材 | 跨项目可复用的城市空镜、交通、办公、科技、人物等画面 |

### 5.1 使用前先做最小归类

素材可以保存在同事自己选择的任意本机硬盘或移动硬盘目录中，CUTROOM 不要求固定路径，也不要求放进项目目录。建议先由人工做一次最小归类，系统再负责扫描、建立索引、搜索和候选匹配；当前版本不会自动移动、重命名或重新整理原片，也不应只依赖 AI 判断素材属于哪个园区。

推荐目录示例（名称和盘符都可以自定义）：

```text
任意自定义路径/
├─ 园区专属/
│  ├─ 园区A/
│  │  ├─ 航拍全景/
│  │  ├─ 区位交通/
│  │  ├─ 厂房楼宇/
│  │  ├─ 配套环境/
│  │  └─ 99_待整理/
│  └─ 园区B/
└─ 通用补充/
   ├─ 城市空镜/
   ├─ 交通物流/
   ├─ 办公商务/
   ├─ 科技制造/
   ├─ 人物服务/
   └─ 99_待整理/
```

整理时遵守以下最小规则即可：

- 园区专属素材按园区分开，一个园区一个独立目录，不要把多个园区混在同一个主素材目录。
- 通用补充素材单独存放，可按城市、交通、办公、科技、人物等场景继续细分。
- 暂时无法判断的素材先放入 `99_待整理/`；有版权、授权或隐私疑问的素材不要放进可用于正式任务的目录。
- 不需要为了 CUTROOM 逐个重命名视频，也不要求一次整理完全部旧素材；先整理近期要制作的园区和常用通用素材即可。
- 后续新增素材只需放入正确目录，再到“镜头素材”点击“检查更新”。

### 5.2 登记与使用

使用步骤：

1. 打开“镜头素材”。
2. 登记本机硬盘或移动硬盘中的真实目录；每个园区目录分别登记为主素材，通用目录登记为通用补充素材。
3. 确认素材库名称和用途，名称建议直接使用园区名或通用素材类型。
4. 点击检查更新，等待扫描和技术探测完成。
5. 创建任务时选择一个主素材目录，并按需勾选通用补充目录。

移动硬盘盘符改变时使用“重新连接”，保留原素材库 ID；不要删除后重新登记。原片不会进入数据库，数据库只保存索引、指纹、代理和时间码。

## 6. 包装素材怎样管理和应用

### 6.1 八类包装素材

- 字幕与字体
- 配音与音色
- BGM
- 音效
- 文字卡
- 贴纸
- 花字
- Logo / 水印

### 6.2 三层目录

| 层级 | 目录 | 用途 |
| --- | --- | --- |
| 核心素材 | `assets/` | 项目自带并统一验证，安装后即可用 |
| 团队扩展 | `asset-packs/` | 团队共享的大型或补充素材包 |
| 个人本地 | 默认 `assets-local/<分类>/inbox/`，也可自定义根目录 | 每位同事自行补充，Git 忽略 |

设计优先级为：个人本地 → 团队扩展 → 核心素材。相同资产 ID 的覆盖必须显示来源，不能静默替换。

每位同事都可以打开“设置 → 存储与缓存”，在“个人包装素材位置”中选择自己的本地文件夹。系统会在所选根目录下自动建立八类 `<分类>/inbox/` 子目录。切换时只更新目录指向，不移动、不复制、也不删除旧目录中的文件；如果移动硬盘或目录暂时离线，原配置会保留，重新接入后可再次选择该目录。

### 6.3 当前实现边界

当前 CUTROOM 已能浏览、筛选、试听和预览核心 manifest 资产，并展示三层目录。包装素材库可执行只读的“检查新增与更新”，报告三层目录中的新增、变化、缺失和无效文件；检查不会自动写入 manifest，也不会自动启用未知授权文件。团队扩展和个人本地素材的人工核验、授权确认及 manifest 登记仍由维护人员完成。

因此现阶段：

- 把文件复制进 `asset-packs/`、默认 `assets-local/` 或自定义个人目录，不等于已经可用于任务；
- 新素材必须由维护人员补齐资产 ID、来源、授权、标签和 manifest 登记；
- 文件缺失、授权不明或外部服务未配置时，不进入正式推荐。

### 6.4 在任务中应用包装

1. 先完成镜头调整并锁定画面。
2. 打开任务的包装方案环节。
3. 试听 BGM、音效和音色，预览字幕、文字卡、贴纸和花字。
4. 整套采用推荐方案，或复制后替换某一项、关闭不需要的可选项。
5. 点击“生成真实预览”，等待最长 12 秒的 9:16 合成片段完成。
6. 播放至 90% 或片尾；只有当前方案和当前画面锁对应的预览完整看过后，确认按钮才会开放。
7. 单独点击确认包装方案；需要复用时可把当前组合保存为个人模板。
8. 确认后才进入正式渲染。

包装素材库是长期资产；任务包装方案只是当前这条视频实际选择的组合。

生成推荐、创建空白组合、复制组合和锁定画面时，按钮会显示处理中并暂时禁用，完成后会显示结果提示。复制组合后自动选中新组合；从包装页返回修改画面并重新锁定后，会回到包装确认阶段。预览失败时使用“重新生成真实预览”，不要反复生成推荐方案；预览成功后需播放至 90% 才能确认。

如果页面显示预览 `stale`、`failed` 或 `missing`，必须重新生成。修改方案或重新锁定画面后，旧预览不会沿用；目录检查发现的未知授权文件也不会自动进入推荐或可选列表。

## 7. 数字人混剪完整流程

准备：

- 禅镜最终数字人口播 MP4；
- 与 MP4 口播完全一致的最终文案；
- 主素材目录；
- 可选通用素材目录；
- 独立模式需要可用的文案策划模型；Agent 模式不需要；

操作：

1. 点击“新建视频”，选择“数字人混剪”。
2. 选择“CUTROOM 自己规划”或“当前 Agent 规划”；独立模式选择文案策划模型，本地素材不足时可选 B-roll 模型。
3. 选择禅镜最终 MP4。
4. 粘贴与 MP4 完全一致的最终口播文案。
5. 选择主素材和通用补充目录，填写用途和目标时长。
6. 运行创建前预检，处理阻断项后创建任务。
7. 人工核对并锁定最终文案。
8. 系统提取声音时间戳、增量同步素材并生成 AI 分镜候选。
9. 逐镜头采用、替换、拆分、删除或调整顺序。
10. 确认全部镜头后锁定画面。
11. 试听并确认本片包装方案。
12. 系统渲染并运行自动 QA。
13. 从头到尾完整播放候选片。
14. 人工确认后生成发布包。

粗剪区显示的是任务实际使用的图片或视频，不是色块示意图。点击下方镜头可逐镜查看，点击“播放”可按当前顺序连续预览；右侧候选素材先点选只会临时预览，只有再点“用所选候选替换当前镜头”并确认影响范围后才会写入任务。图片镜头不会显示无效的入点/出点裁剪控件；绑定了视频片段的镜头才可裁剪。任一镜头素材离线、越界或格式不支持时，页面会指出具体镜头并禁用“确认粗剪并锁定画面”，重新连接或恢复素材后才可继续。

数字人口播始终是声音主轴；B-roll 全屏或画中画出现时仍保留数字人口播声音。

## 8. 信息流广告混剪完整流程

准备：

- 已定稿的广告文案；
- 投放目的、目标时长和画幅；
- 主素材与可选通用素材目录；
- 独立模式需要可用的文案策划模型；Agent 模式不需要；
- 可用的配音服务，且已刷新出中文音色目录。

操作：

1. 点击“新建视频”，选择“信息流广告混剪”。
2. 选择规划方式和配音服务；独立模式再选择文案策划模型，B-roll 模型可选。
3. 在始终可见的“本条视频音色”中确认常用音色或改选其他声音，并可先试听。
4. 填写最终广告文案、用途、时长和画幅。
5. 选择主素材和通用补充目录，运行预检并创建任务。
6. 人工锁定广告文案。
7. 系统按锁定原文逐句生成分镜和 TTS。
8. 系统只在任务绑定的素材库中逐句配片。
9. 检查每句话的声音、画面、字幕和节奏。
10. 任何一句没有真实素材时，补选素材后才能锁定画面。
11. 确认包装方案，渲染并运行自动 QA。
12. 从头到尾完整观看候选片。
13. 人工确认后生成发布包。

广告成片使用已确认的素材起止位置和字幕样式。若选段不够长或已经失效，请返回镜头调整后重新确认。

## 9. 四个人工门禁

系统不能代替以下四个决定：

1. 最终文案确认；
2. 画面和顺序确认；
3. 本片包装方案确认；
4. 完整观看后的成片确认。

自动测试或自动 QA 通过，不代表业务内容、事实、节奏和最终观看体验已经通过。

## 10. 审片和发布包

自动 QA 的“素材授权待核对”只表示系统还没有来源记录，不能从“文件在本地”推断为可商用。画面锁定后即可在包装阶段核对，不必先出一版会被阻断的成片。若本片锁定的镜头**全部由团队自摄且可用于商业发布**，选择“确认镜头素材为团队自摄并复用”；系统按素材身份和指纹登记，后续任务可复用，文件内容变化后须重新确认。若素材来自第三方但已取得本片使用授权，选择“仅确认本片镜头素材可商用”，不会把它登记为团队自摄。若已经生成旧候选，在 QA 页补确认后仍须重新渲染并质检；旧报告不会被改写。

质检会把已知照片镜头的静止画面视为正常画面，仍会提示视频镜头中的异常冻结。非阻断警告不会暗中挡住审片，但应在完整观看时人工检查；真峰值超出当前任务的发布阈值仍是阻断，需要生成达标的新候选。

审片时至少检查：

- 字幕是否与声音同步；
- 文案数字、地点、机构和政策表述是否准确；
- 画面是否与当前句子匹配；
- 单一镜头是否停留过久；
- 转场是否生硬；
- 人声是否清晰，BGM 是否压人声；
- Logo、水印、花字和贴纸是否遮挡重要信息；
- 是否出现隐私、未授权素材或不适合发布的内容。

发布文案检查未通过时，修改标题或说明后可重新生成发布包；系统保留旧包并生成新版本。同样内容的重复提交复用仍完整有效的包。

标准发布包包含七个文件：

1. `video-final.mp4`
2. `cover-01.jpg`
3. `cover-02.jpg`
4. `cover-03.jpg`
5. `publish-copy.md`
6. `publish-check.json`
7. `qa-report.md`

当前不自动上传到抖音、视频号或小红书。

## 11. 中断和常见问题

### 模型显示不可用

- 检查 API Key、请求地址和精确模型 ID；
- 确认账号已经开通该模型；
- 重新点击测试连接；
- 超过 24 小时未检测时重新测试；
- 任务不会自动换到另一个模型。

### 任务中断

只使用页面显示的“从安全检查点继续”。付费调用结果不明确时系统不会自动重试，避免重复扣费。

### 素材目录离线

连接移动硬盘后使用重新连接；不要新建重复素材库。

### 包装素材不能选择

检查详情中的状态和预期路径。文件缺失、授权不满足或尚未登记时不能用于正式任务。

### 空间不足

打开“设置 → 存储与缓存”：

1. 点击预览清理范围；
2. 核对数量和预计释放空间；
3. 再点击确认清理。

系统只清理登记过且可重建的预览缓存，不删除原片、数据库、文案和最终成片。

## 13. 管理员和维护人员注意事项

- 不直接编辑生产 SQLite。
- 不把 API Key、Token、Cookie、客户素材或个人隐私写入文档和 Git。
- 每台新电脑由火山账号/IAM 管理员录入一次豆包新版 API Key 和 AK/SK；旧版 AppID + Access Token 仅作兼容，可以留空。不要经微信、文档、Git 或 ZIP 分发密钥。
- 不手工删除任务目录或发布包。
- 新增包装素材时补齐资产 ID、来源、授权、版本、文件路径和预览。
- 核心素材可进入 `assets/`；团队扩展进入 `asset-packs/`；个人试用素材进入设置页显示的个人目录下 `<分类>/inbox/`。
- 团队/个人素材自助扫描尚未接通前，由维护人员登记，不向普通同事宣称复制文件即可使用。

## 14. 升级、回退和卸载

### 14.1 升级

1. 关闭旧版 CUTROOM，不要覆盖原目录。
2. 备份旧版的 `runtime/workbench/catalog.sqlite`，并保留设置页显示的个人包装素材根目录（未自定义时为 `assets-local/`）。
3. 把新版 ZIP 解压到一个新目录，运行新版 `安装CUTROOM.bat`。
4. 由维护人员确认数据库迁移和本地素材路径后，再改用新版 `启动CUTROOM.bat`。
5. 至少完成一条测试任务后，才删除旧版目录。

模型密钥保存在 Windows 凭据管理器，不应复制到新目录或写入文档。同一电脑、同一 Windows 用户升级并复制原数据库时，已有凭据引用继续可用；换电脑或换 Windows 用户后必须由管理员重新录入。beta.2 首次打开旧数据库会自动执行迁移 030 并导入原有常用音色，但仍应先保留数据库备份。

beta.6 首次启动会自动执行迁移 032，增加审片计时字段。请先关闭旧服务并保留升级前数据库备份；更换广告镜头或字幕包装后必须重新渲染和完整审片，旧候选不能直接发布。

beta.7 补齐数字人与信息流的真实粗剪、包装预览、候选版本、QA、完整审片、返工和发布包闭环，并修正信息流粗剪页误用数字人口播主轴的说明。园区宣传片仍未开放。

beta.7 安装器会把依赖安装临时文件放在当前 CUTROOM 目录的 `runtime\install-temp` 下，避免系统共享临时目录在首次安装过程中被清理。安装完成后该目录可保留；安装失败时不要手动删除，维护人员可据此排查。

### 14.2 回退

关闭新版后，重新打开旧版目录中的 `启动CUTROOM.bat`。若数据库已由新版升级，应由维护人员先恢复升级前备份，不能让旧版直接打开不兼容的新数据库。

### 14.3 卸载

先关闭 CUTROOM 服务，再删除对应的完整解压目录即可。CUTROOM 不会删除登记在其他磁盘上的原始媒体库，也不会删除自定义的个人包装素材目录；删除前仍要单独备份 `runtime/workbench/catalog.sqlite` 和需要保留的个人包装素材。

### 14.4 第三方素材署名

使用 Scott Buckley 的 BGM 发布视频时，必须在视频发布文案、平台说明、片尾或其他随作品展示的位置加入对应署名；不要求一定写在视频封面。具体曲目文字见根目录 `THIRD_PARTY_NOTICES.md`。如果发布渠道完全没有可展示署名的位置，就不要使用这些曲目。
