# 溯剪 × Cutroom：统一制作入口（第一版）

## 使用方式

1. 在溯剪解析参考视频。
2. 点击“制作新视频／保存草稿”，将本次分析保存为剪法模板。
3. 输入新脚本，选择 Cutroom 中的园区素材库和配音配置。
4. 确认素材使用权、本次费用及常规选镜/包装自动确认委托，生成预览。
5. 在溯剪审看预览，阅读质检提示与还原差异，然后保存可编辑剪映草稿。
6. 首次采用的包装组合可同步为 Cutroom 个人模板，下一次随剪法模板复用。
7. 在“预览与剪映草稿生成”的“调整预览包装”中选择字幕、边框／水印，或展开音乐、音效、贴纸、标题卡与花字选项。点击“更新当前预览（复用配音）”会在同一任务内克隆包装方案并重新渲染，不调用配音或重新选镜。

更新包装前的执行记录与草稿蓝图保存在 `preview_history/`，Cutroom 的旧候选视频也会保留。新版不会覆盖已保存的剪映工程；审看后可另存新版草稿。当前仅提供目录内可实际渲染的包装项，字幕仍是近似样式，镜头节奏与精确花字复刻不属于包装开关。

原有分析页面、蓝图和兼容接口保留。旧的多按钮向导不再作为本机工作台主入口。
分析页现在按五步排列：原视频与分轨 → 字幕分析 → 配音与画面文字 → 溯剪 × Cutroom → 预览与草稿。
左侧提供本机真实历史任务、搜索、折叠与五步跳转；分析音轨通过受限路径接口试听。
历史列表只读取本机记录，不会为刷新任务状态触发任何供应商调用。
Cutroom 的后台服务/工作进程须正常运行；仅发现项目目录不代表后台执行器在线。
溯剪继续使用 8788 端口。Cutroom 自己的服务地址不受这个端口设置影响。

## 职责与数据

- `edit_blueprint.json`：参考视频分析，不因新脚本生成而改写。
- `templates/editing/st-*.json`：完整剪法配方及分析摘要绑定；包装组合只是它的一部分。
- `generation_blueprint.json`：本次新脚本、选镜和真实配音时间线，与旧版固定槽位草稿分离。
- `execution.json`：一次 Cutroom 执行的任务编号、费用委托、队列阶段、结果及错误。
- `execution_plan.json`：从实际 `adrender.json` 冻结的镜头、文字、声音和图层；绑定候选版本及文件校验值。
- `execution_history/<task_id>/`：切换到另一次生成前保留旧执行记录。

网页保存的 Cutroom 模板是实际已确认的包装组合，不会宣称它包含全部参考视频结构。
导出的原生草稿不使用烧好字幕的预览 MP4 作为主素材。

## 当前已经接通

- Cutroom 已配置素材库、配音配置和个人包装模板的安全读取；不复制或返回密钥。
- 创建前真实预检、创建任务、锁定脚本、同步素材、提交分镜、配音任务排队。
- 按用户事先委托核验素材可读性、自动确认镜头与包装。
- 参考字幕颜色映射到适用且已获商业使用许可的目录预设；已保存包装优先复用。
- 时间线以 Cutroom 实际生成的配音结果为准，不强制塞进参考片固定时长。
- 在溯剪内播放 Cutroom 生成预览，显示真实质检阻断和已知差异。
- 从原始素材创建独立视频片段、字幕/标题/基础花字、配音、BGM、音效及图片图层。
- 素材复制进草稿，校验源文件/副本，使用真实剪映草稿库 `Projects/com.lveditor.draft`。
- 重复保存同一版本返回已有草稿，不覆盖可能已被人工编辑的工程。
- 填写独立草稿标识、名称、时长，并备份后登记剪映草稿列表；剪映运行时不竞争其自动保存。

## 明确未完成的能力

- 自动选镜目前是透明的文件名/类别匹配，不是对素材画面的专业语义理解。
- 尚未将参考视频的全部运动、逐事件音效和复杂包装精确重建。
- 没有从压平成片恢复剪映原生花字/贴纸编号，也没有缓存所有剪映素材库。
- 原生字幕字体是剪映内近似字体；预览的 ASS 包装不保证像素级一致。
- 原生叠化边界、侧链 ducking 和整体响度处理与 FFmpeg 预览存在差异。
- 本机原生草稿文件生成成功不等于已经在用户安装的剪映版本中打开验收。
- 不自动发布，不伪造人工完整观看，不跳过素材授权或改写质检通过状态。

## 安全、恢复与费用

只接受本机同源 JSON 写请求。任务根、素材库和草稿位置由服务配置及 Cutroom 目录控制，
不接受网页任意指定系统路径。未开放的 Cutroom 操作不能穿过本地桥接层。

已知 MCP 暂未提供常规确认、模板保存等操作，因此本版使用薄的本地兼容适配器：
在 Cutroom 自己的虚拟环境中调用其现有领域函数与 AgentGateway，不复制源码，不直接修改数据库表。
后续 MCP 暴露同等能力时只替换这层传输；网页和蓝图不需要重做。

配音调用使用稳定请求编号，结果不明确时停止并提示核对，不自动再次收费。
模型可用性检测过期时，在本次费用确认覆盖下调用 Cutroom 原有真实检测（短句“连接测试”），
不把历史检测时间直接改为当前。新预检不通过则不创建任务。

服务中断后，网页可恢复已知任务；创建结果不明确且没有任务编号时不能盲目重新创建。
新的默认配置可以通过 `SUOJIAN_CUTROOM_ROOT`、`SUOJIAN_JIANYING_DRAFT_ROOT` 指定。

# 配音音色选择

统一制作入口现在会读取 Cutroom 已配置服务的音色目录，可搜索名称、性别、语言和风格，再选择本次生成使用的音色。音色会随任务提交给 Cutroom，保存在本次配置中，并参与生成去重；切换音色会生成新的配置标识，不会误用另一音色的已有结果。

目录和密钥继续由 Cutroom 管理，网页只读取音色公开信息。当前已配置豆包服务的目录包含 103 个可选音色（目录更新于 2026-09-30）。新增服务或更新供应商音色后，请先在 Cutroom 更新目录，再刷新溯剪。选择和搜索音色不调用配音合成。
